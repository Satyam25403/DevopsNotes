THE CAUSE ISOLATION
🔬 NETWORK NAMESPACES
Docker gives each container its own isolated network namespace. Every container has its own loopback interface — its own private "localhost". They're completely separate.
EACH CONTAINER HAS ITS OWN 127.0.0.1
WHAT "localhost" MEANS WHERE
Your laptop → your machine's :5000
Frontend container → frontend container's :5000
Backend container → backend container's :5000
⚠ All three are DIFFERENT addresses!
💡 MENTAL MODEL
Think of each container as a separate machine. Would you use localhost to call a different machine? No — you'd use its hostname or IP. Same rule applies here.
Each container is like a separate machine with its own 127.0.0.1.
localhost only ever reaches the container you're already inside.

HOW COMPOSE NETWORKING WORKS
docker-compose.yaml
services:
frontend: # ← this is the hostname
build: ./frontend
environment:
API_URL: http://backend:5000
backend: # ← use THIS as hostname
build: ./backend
ports: ["5000:5000"]
THE RULE
Compose auto-creates a network. Each service joins it. Each service's name becomes its DNS hostname. Use the name, not localhost.
⚠ This only works container-to-container. From your browser (outside Docker), you still use localhost + the mapped port.
Compose puts services on a shared network. Names become hostnames.
Replace localhost with the service name. That's the entire fix.
