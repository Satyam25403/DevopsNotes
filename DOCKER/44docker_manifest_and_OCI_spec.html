OVERLAYFS LAYER STACK (bottom → top)
▸ EACH LAYER IS A tar.gz DIFF
Each Dockerfile instruction that changes the filesystem
(RUN, COPY, ADD) creates a new layer containing only
the delta — added, modified, or whiteout-deleted files.
OverlayFS merges them into a single unified view at runtime.
▸ ORDERING MATTERS FOR CACHE
✗ BAD ORDER
COPY . /
RUN apt install
← code change
busts apt cache
✓ GOOD ORDER
RUN apt install
COPY . /
← apt layer
reused always
Layers are content-addressed — same sha256 digest = same bytes, cached everywhere.
Order Dockerfile instructions from least-to-most frequently changed to maximise cache hits.

▸ OCI vs DOCKER SPEC
OCI Image Spec (opencontainers.org) is the open standard.
Docker's format predates it but is now aligned.
MediaType tells you which spec a manifest uses:
vnd.oci.* = OCI · vnd.docker.* = Docker legacy
One tag can point to an index containing per-arch manifests — transparent to the user.
Use digest pinning per-arch in CI to guarantee reproducibility across platforms.
