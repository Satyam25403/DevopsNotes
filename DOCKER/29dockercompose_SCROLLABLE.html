THE PROBLEM PAIN
⚠ YOUR TYPICAL APP STACK
Running a modern app means juggling containers — a database, a backend, a frontend, a cache, a queue. Without Compose, you manage each one manually.
terminal — the hard way
$ docker network create myapp-net
$ docker run -d --name postgres \
--network myapp-net -e POSTGRES_PASSWORD=secret \
-v pgdata:/var/lib/postgresql/data postgres:15
$ docker run -d --name redis \
--network myapp-net redis:alpine
$ docker run -d --name backend \
--network myapp-net -p 8000:8000 \
-e DATABASE_URL=postgres://... myapp-backend
$ docker run -d --name frontend \
--network myapp-net -p 3000:3000 myapp-frontend
$ docker run -d --name worker \
--network myapp-net -e REDIS_URL=redis://... myapp-worker
😱 And if anything crashes, do it all again...
✗ ORDER MATTERS
Network must exist before containers. DB before backend. Easy to forget.
✗ NO MEMORY
Flags live in your shell history. New teammate? Good luck.
✗ TEAR DOWN
Stop each container. Remove each. Remove network. Remove volumes.
✗ ENV DRIFT
Your env vars differ from your teammate's. Bugs only on their machine.
Every service needs its own flags, network, volumes, env vars.
This is the problem Docker Compose was built to solve.

THE SOLUTION YAML
✓ docker-compose.yaml
One declarative YAML file describes your entire stack. Services, networks, volumes, env vars — all versioned, all shared, all reproducible.
docker-compose.yaml
services:
db:
image: postgres:15
environment:
POSTGRES_PASSWORD: secret
volumes: [pgdata:/var/lib/postgresql/data]
redis:
image: redis:alpine
backend:
build: ./backend
ports: ["8000:8000"]
depends_on: [db, redis]
frontend:
build: ./frontend
ports: ["3000:3000"]
worker:
build: ./worker
depends_on: [redis]
volumes:
pgdata:

KEY CONCEPTS ESSENTIALS
WHAT COMPOSE MANAGES FOR YOU
🔗
SERVICES
Each container is a "service". Services find each other by name — backend can reach db just by hostname db.
🌐
NETWORKS
Compose auto-creates a private network. All services join it. No --network flags needed. Isolated from other apps.
💾
VOLUMES
Named volumes declared once, shared across containers. Data persists even when you docker compose down.
⚙️
DEPENDS_ON
Startup ordering. Tell Compose that backend must wait for db. No more race conditions.
compose cheat sheet
docker compose up # start all
docker compose up -d # start detached
docker compose down # stop + remove
docker compose down -v # also delete volumes
docker compose logs -f # tail all logs
docker compose ps # list services
docker compose build # rebuild images
docker compose exec db bash # shell in service
Compose is the standard way to develop multi-service apps locally.
