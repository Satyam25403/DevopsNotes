VM is an entire operating system with its own kernel, hardware drivers, programs, and applications, creating which is an overhead
container is simply an isolated process with all of the files it needs to run.(Slef-contained, Isolated(file system), independent and portable)
A container image is a standardized package that includes all of the files, binaries, libraries, and configurations to run a container.(Immutable and layered)
Registry is a centralized location for storing and sharing your container images. It can be either public or private.

Installation:

uninstall all conflicting packages(unofficial docker packages):
>sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-compose-v2 docker-doc podman-docker containerd runc | cut -f1)

1.Setup docker's apt repo:
# Add Docker's official GPG key:
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add the repository to Apt sources:
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update

2.Install docker packages:
>sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

3.Start docker:
>sudo systemctl start docker

4.Verify running status:
>sudo systemctl status docker

5.Verify installation succes:
>sudo docker run hello-world

Docker in docker:

🧠 Alternative(in place of installation): Use Host Docker from Inside Container
If your goal is just to run Docker commands from inside the container, you can mount the host’s Docker socket:
>docker run -v /var/run/docker.sock:/var/run/docker.sock -it ubuntu
This lets you use the host’s Docker daemon without needing to start one inside the container.

If your goal is to run Docker inside Docker, the recommended way is to use the official Docker-in-Docker image:
>docker run --privileged --name dind-test -d docker:dind

What Are Dangling Images in Docker?
Dangling images are Docker images that:
Have no name (tag) → their repository and tag are <none>:<none>
Are not used by any container like these:
REPOSITORY          TAG       IMAGE ID       CREATED         SIZE
<none>              <none>    abc12345defg   10 minutes ago  300MB
They are intermediate build layers or outdated images left behind

Remove only dangling images:
docker image prune

Remove all unused images (dangling + unreferenced(nolonger being used by containers)):
docker image prune -a

RUN vs ENTRYPOINT vs CMD
RUN Purpose:
Used during the image build process.
Executes commands once when building the image (like installing packages or setting up files).
RUN apt update && apt install -y curl

CMD Purpose:
Provides default arguments or a command to run when the container starts.
Can be overridden when starting a container using docker run.
CMD ["python", "app.py"]
overridable while running=> docker run my-image python other_script.py

ENTRYPOINT Purpose:
Defines the main executable for the container.
Not easily overridden (unless using --entrypoint flag).
ENTRYPOINT ["python"]
CMD ["app.py"]

RUN builds the image, CMD runs the container

---

Overriding container defaults:
docker container starts with default command and configuration defined in its image(CMD, ENTRYPOINT, ports, env vars etc.) when it runs.
docker allows us to override these defaults at runtime using flags at docker-run.
1.Override network ports:(-p)
>docker run <HOST-PORT>:<CONTAINER-PORT> <image>            :helps running multiple instances of same container without port conflicts
ex:
>docker run -d -p 5432:5432 postgres
>docker run -d -p 5433:5432 postgres

2.Set env vars:(-e or --env-file)
>docker run -e <POSTGRES_PASSWORD>=<password> <image>
>docker run --env-file .env <image>

3.Restrict overuse of host resources(CPU and memory):(--memory, --cpus)
>docker run --memory="<512>m" --cpus="<0.5>" <image>
monitor usage:
>docker stats

4.Use custom docker networks:(--network)
containers by default connect to bridge network. Custom network provides name-based DNS resolution and better isolation.
>docker network create <networkname>
>docker run --network <networkname> <image>

5.Override CMD and ENTRYPOINT:
a.compose.yaml
services:
    <postgres>:
        image: <postgres>
        entrypoint: ["docker-entrypoint.sh", "postgres"]
        command: ["-h", "localhost", "-p", "5432"]
b.docker run:
>docker run <image> <docker-entrypoint.sh> <-h localhost -p 5432>

Publishing and exposing ports:
containers provide isolated processes for each component of application(react frontend, python api, database etc) each runnning in its own sandboxed environment completely isolated
from everything on your host machine. Isolation is good for security and managing dependencies but that also means you cant access them directly(ex: you cant access the web app in browser)

publishing a port gives ability to access containers by setting up a forwarding rule:
>docker run -d -p HOST-PORT:CONTAINER-PORT <imagename>

HOST-PORT: port on machine where you want to receive traffic
CONTAINER-PORT: port within the container that's listening for connections
NOTE: when a port is published, it is published to all network interfaces by default...meaning traffic reaching the published port cann access the published application
(thats y it is not recommended to publish databases)

Ephermal ports:
when we want docker to choose which port to publish and are ok with any port, we simply omit HOST-PORT
>docker run -p <CONTAINER-PORT> <image>
port chosen by docker is called Ephermal port and is seen once the container is running by:
>docker ps

publishing all ports:
while creating an image using dockerfile, EXPOSE instruction is used to indicate that the packaged application will use specified port, but they are not published by default.
with -P, we can automatically publish all exposed ports to ephermal ports(docker chooses on host). Use when you want to avoid port conflicts in development or testing.
>docker run -P <imagename>
