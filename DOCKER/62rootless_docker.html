UID REMAPPING VIA USER NAMESPACES
newuidmap / newgidmap
Kernel helpers that allow unprivileged users to set up UID/GID mappings. They validate against /etc/subuid and /etc/subgid before writing to /proc/self/uid_map.
THE KEY INSIGHT
Container's root (uid=0) maps to host uid=100000+ — an unprivileged user on the host. A container breakout gets you nobody, not root.
User namespaces remap UIDs inside the container.
Container root = unprivileged host user. Escape = nothing.

WHAT YOU GIVE UP IN ROOTLESS MODE
TRADE-OFFS KNOWN LIMITS
✗ NO LOW PORTS (<1024)
Can't bind to ports 80, 443, 22 directly. Use ports ≥1024 and put a reverse proxy (nginx, traefik) in front. Or set net.ipv4.ip_unprivileged_port_start=80 via sysctl.
✗ LIMITED NETWORK MODES
Only slirp4netns or pasta available (no macvlan, ipvlan, overlay). Performance slightly lower than root Docker; latency add ~5-10µs per packet.
⚠ APPARMOR / CGROUPS v1
Cgroup v2 required for resource limits (CPU/memory). AppArmor profiles need adjustment. Check: cat /sys/fs/cgroup/cgroup.controllers
✓ PODMAN: ROOTLESS BY DEFAULT
Podman ships rootless from day one — no setup needed. Drop-in docker replacement: alias docker=podman. Also supports Kubernetes pods without root.
Ports below 1024 and some network modes unavailable.
Massively reduced attack surface justifies these trade-offs.
