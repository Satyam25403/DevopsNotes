EACH CONTAINER'S VIEW OF "LOCALHOST"
WHY IT FAILS
Each container has its own network stack. "localhost" inside the frontend resolves to 127.0.0.1 of that container — not your host, not the backend. There is no backend there.
localhost means "this container" — not the other one.
Your backend is unreachable via localhost from another container.

DOCKER DNS RESOLUTION FLOW
HOW IT WORKS
Docker injects a DNS resolver (127.0.0.11) into every container on a custom network. When you say "backend", it maps the container name to its internal IP automatically.
Custom networks get a built-in DNS server at 127.0.0.11.
Container name = hostname. Docker resolves it automatically.

⚠ DEFAULT NETWORK = NO DNS
The default "bridge" network does NOT support DNS. You must create a custom network (or use Compose) to get name resolution.
★ DNS vs PORT MAPPING
-p exposes to your host machine.
DNS names work container-to-container.

THE GOLDEN RULE
USE THIS PATTERN
http://<service-name>:<port>
service-name = key in docker-compose.yml
port = what the app listens on internally
Custom networks unlock DNS. Default bridge does not have it.
http://<service-name>:<port> is the pattern to memorise.
