HOW ISOLATION ACTUALLY WORKS
NAMESPACES LINUX MAGIC
LINUX NAMESPACES = THE SECRET SAUCE
PID NAMESPACE
Container thinks PID 1 is its init process. Host OS sees real PID 4782. Each container has its own process tree.
container: PID 1host: PID 4782
NET NAMESPACE
Own IP, own ports, own routing table. Container on port 3000 doesn't conflict with another on port 3000.
eth0: 172.17.0.2eth0: 172.17.0.3
MNT NAMESPACE
Container sees its own filesystem root (/). Can't touch host files or other containers' data.
/app → isolatedhost: /var/lib/docker
CGROUPS: RESOURCE LIMITS
CPU, RAM, I/O capped per container. One greedy app can't starve others on the same host.
cpu: 0.5 coresmem: 512 MB
KEY INSIGHT: NOT A VM
Containers are just processes with extra rules. The kernel isn't fooled — it sees every container process directly.
