FROM — the base image
Every image starts from another image. node:20-alpine gives you Node.js 20 on top of Alpine Linux (~50 MB). You build on top of this.
required — must be first
WORKDIR — your working dir
Sets the default directory for all following commands. Created if it doesn't exist. Like cd /app && mkdir -p in one step.
all COPY/RUN happen here
COPY + RUN — install deps first
Copy package.json first (not all code). Run npm install. This layer is cached — rebuild only if package.json changes.
cache trick — critical
COPY . . — your app code
Copy everything else (your source files). This is separate from deps so editing your code doesn't re-run npm install. Fast rebuilds.
host → container /app
CMD — runs when container starts
Not run during build. Executes when you do docker run. Array form is preferred — avoids shell wrapper overhead.
only one CMD per Dockerfile
Dockerfile = recipe for your image
Each instruction creates a layer. Docker caches layers — unchanged layers aren't rebuilt. Order matters: slow-changing stuff first.

WHAT EACH INSTRUCTION ACTUALLY DOES
INSTRUCTIONS REFERENCE
5 INSTRUCTIONS YOU'LL USE IN EVERY DOCKERFILE
FROM
Set the base image. First instruction always.
FROM node:20-alpine
FROM python:3.12
FROM ubuntu:22.04
WORKDIR
Set + create working directory for all subsequent commands.
WORKDIR /app
WORKDIR /home/node
COPY
Copy files from host into the image at build time.
COPY . .
COPY src/ /app/src
COPY pkg*.json ./
RUN
Execute a command during build. Creates a new layer.
RUN npm install
RUN apt-get update
RUN pip install -r req
CMD
Default command when container starts. NOT run at build time.
CMD ["node","index.js"]
CMD ["python","app.py"]
CMD ["nginx","-g","..."]
⚠ RUN vs CMD — most common confusion
RUN
Runs during
docker build
Creates a layer
Sets up the image
CMD
Runs during
docker run
Not a layer
Starts your app
BONUS INSTRUCTIONS YOU'LL MEET SOON
EXPOSE Documents which port the container listens on (hint only)
ENV Set environment variables available at build AND runtime
ARG Build-time variables only — not available after build
ENTRYPOINT Like CMD but harder to override — for container executables
RUN = build time. CMD = run time.
Every RUN creates a new cached layer. Chain commands with && to keep layers thin: RUN apt update && apt install -y curl

💡 THE CACHE TRICK — WHY ORDER MATTERS
Edit index.js → only layer 4 rebuilds (0.3s total)
Edit package.json → layers 3+4 rebuild (4s+ total)
Rule: change less often = higher in the stack
-t myapp:1.0 = tag the image with a name
The . at the end is the build context — the folder Docker sends to the daemon. Everything in that folder can be COPYed in.

$docker run -d -p 3000:3000 myapp:1.0

$docker build -t myapp:1.1 .
