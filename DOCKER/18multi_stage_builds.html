TWO STAGES — ONE DOCKERFILE
BUILDER STAGE → RUNTIME STAGE
DIAGRAM THE PATTERN
MULTI-STAGE BUILD FLOW
01
The builder stage has everything needed to compile: full node, TypeScript, devDependencies, source. It produces dist/. Then it's thrown away entirely.
02
COPY --from=builder copies only the compiled artifacts from the builder stage. The runtime stage starts fresh from a tiny alpine base and receives just what production needs.
03
The builder image never gets pushed to your registry. Docker handles it internally. You write one Dockerfile, run one docker build, get one tiny image. No scripts needed.
THE KEY INSTRUCTION
COPY --from=builder /app/dist ./dist
That one flag -- from=builder -- is the entire magic. It copies files across stage boundaries. Everything else in the builder stage evaporates. No traces in the final image.

THE DOCKERFILE
NODE + TYPESCRIPT — COPY-PASTE READY
CODE COPY-PASTE
Dockerfile — multi-stage Node/TypeScript
# ═══════════════ STAGE 1: BUILD ═══════════════
FROM node:18 AS builder
WORKDIR /app
# cache layer: deps change rarely
COPY package*.json ./
RUN npm ci
# source code changes often — last
COPY . .
RUN npm run build
# ═══════════════ STAGE 2: RUNTIME ═══════════════
FROM node:18-alpine
WORKDIR /app
ENV NODE_ENV=production
# prod deps only
COPY package*.json ./
RUN npm ci --omit=dev
# ← THE MAGIC: copy only built artifacts
COPY --from=builder /app/dist ./dist
# non-root for security
USER node
EXPOSE 3000
CMD ["node","dist/index.js"]
KEY LINES EXPLAINED
AS builder → names the stage so we can reference it later
node:18-alpine → 42MB vs 350MB for node:18. Alpine Linux is minimal.
--omit=dev → installs only dependencies, not devDependencies. ~10× smaller.
--from=builder → cross-stage file copy. This is the entire multi-stage mechanism.
USER node → run as non-root. Security best practice. node user exists in alpine.
💡
You can have more than 2 stages — e.g. a test stage between builder and runtime. Docker skips intermediate stages not referenced by the final stage unless you explicitly target them.
BONUS: npm ci --omit=dev
Installs only production dependencies
devDependencies (TypeScript, ESLint, Jest, etc.) can be 10× larger than prod deps. --omit=dev (formerly --production) strips them. Combine with --from=builder and you save hundreds of MB.

THREE REASONS TO USE MULTI-STAGE
🚀
FASTER DEPLOYS
50MB pulls 18× faster than 900MB. On a 100Mbps connection: 4 seconds vs 72 seconds. In Kubernetes with 50 pods scaling up simultaneously: 3.3 minutes saved per rollout.
🔒
SMALLER ATTACK SURFACE
Fewer packages = fewer CVEs. A TypeScript compiler in production is dead code that attackers can exploit. No compiler = no RCE via compiler bugs. No source code = no IP theft via container escape.
💰
LOWER STORAGE COSTS
ECR/GCR/ACR charge per GB stored. 10 image versions × 50MB vs 900MB = $0.50 vs $9 per month. Multiply by 50 services. Savings compound fast with many microservices.
