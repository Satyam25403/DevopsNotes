PART 1 OF 4 LAYERS
🐳 DOCKER IS NOT ONE THING
When you type docker run, you trigger a chain of 4 separate components. Most developers only see the top layer. Let's follow the call all the way down to where the container process actually starts.
DOCKER RUNTIME STACK — TOP TO BOTTOM
docker CLI
UX wrapper. Talks to dockerd over a socket. You never skip this layer as a dev.
dockerd
The daemon. Handles networking, volumes, image management. Delegates to containerd.
containerd
The actual container runtime. Pulls images, manages lifecycle. CNCF graduated project.
runc
Low-level OCI runtime. Calls clone(), setns(), pivot_root(). Spawns the PID 1 process.
docker run triggers a 4-layer call chain before any process starts.
Most of Docker's "magic" lives in containerd and runc.

PART 2 OF 4 CRI
🔌 CONTAINER RUNTIME INTERFACE
CRI is a gRPC API that Kubernetes kubelet uses to talk to container runtimes. It defines two services: RuntimeService (pods, containers) and ImageService (pull, list, remove). Any runtime that implements CRI can work with Kubernetes.
KUBERNETES ↔ CRI ↔ RUNTIME
containerd
General purpose. Used by Docker AND Kubernetes. CNCF graduated. Plugin ecosystem.
CRI-O
Kubernetes-only runtime. Minimal, purpose-built. Default in OpenShift. RedHat backed.
CRI is the gRPC contract between kubelet and any compliant runtime.
containerd and CRI-O both implement CRI. runc does the kernel work.

DOCKERSHIM REMOVED — WHY IT MATTERS
PART 3 OF 4 K8S 1.24
⚠ THE GREAT DOCKERSHIM PANIC
In May 2022, Kubernetes 1.24 removed dockershim — an adapter that let kubelet speak to Docker's non-CRI API. Many devs thought "Kubernetes dropped Docker". It didn't. It dropped the compatibility shim.
BEFORE K8S 1.24 → AFTER K8S 1.24
✓ YOUR IMAGES STILL WORK
OCI images are OCI images. containerd pulls them the same way. Zero migration needed for image format.
✗ docker.sock SCRIPTS BREAK
DaemonSets mounting /var/run/docker.sock for CI need updating. Use crictl or nerdctl instead.
→ YOU STILL USE DOCKER LOCALLY
docker build / docker run on your laptop is unaffected. Only K8s node runtime changed.
K8s dropped the dockershim adapter — not Docker images or Dockerfiles.
kubelet now talks directly to containerd via CRI. Cleaner, faster.

PART 4 OF 4 OCI
📦 OCI — OPEN CONTAINER INITIATIVE
OCI defines two standards: image-spec (what a container image looks like) and runtime-spec (how to run one). Docker, containerd, CRI-O all follow OCI. runc is the reference OCI runtime implementation.
CONTAINER RUNTIME LANDSCAPE
💡 AFTER DOCKERSHIM — USE CRICTL
$ crictl ps # list containers
$ crictl images # list images
$ crictl logs <id> # view logs
$ nerdctl run nginx # docker-like UX
OCI specs mean all these runtimes share the same image format.
Build once with Docker. Run anywhere: containerd, CRI-O, K8s.
