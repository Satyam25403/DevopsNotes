📜 EXPOSE IS DOCUMENTATION
EXPOSE does NOT open any port on the host. It is a hint inside the image telling other developers (and Docker) which port the app listens on. Nothing is reachable yet.
⚠️ COMMON MISTAKE
Many beginners write EXPOSE 80 and wonder why they cannot reach the container. The actual port binding happens at docker run time with -p or -P.
EXPOSE is metadata — like a comment with extra steps.
No ports published until you use -p or -P at run time.

🔁 PORT MAPPING SYNTAX
-p 8080:80 → host 8080 to container 80
-p 443:443 → same port on both sides
-p 3000:3000 -p 5000:5000 → multi port
🌐 BINDS TO 0.0.0.0 BY DEFAULT
Without specifying an IP, -p binds to 0.0.0.0 — all network interfaces. On a cloud VM with a public IP, port 8080 is reachable from the internet!
-p 8080:80 opens host port 8080 → container 80.
Default binds to 0.0.0.0 — all interfaces including public IPs.

☁️ CLOUD VM GOTCHA
Most cloud VMs have a public IP on eth0. Docker binding to 0.0.0.0 exposes your container to the internet — even without explicit firewall rules. Always use 127.0.0.1 binding for internal services.
0.0.0.0 means ALL interfaces — public IP included.
Use -p 127.0.0.1:8080:80 to restrict to localhost only.

-P FLAG (UPPERCASE)
AUTO PUBLISH ALL EXPOSE PORTS
-P AUTO-PUBLISH EPHEMERAL
terminal
$ docker run -P nginx
# publishes ALL EXPOSE'd ports
$ docker port my-container
80/tcp -> 0.0.0.0:49153
# random ephemeral port!
🎲 EPHEMERAL PORTS 32768-60999
Docker picks random high ports from the ephemeral range. Use docker port <name> to find which port was assigned. Changes on every restart!
🗺️ WHEN TO USE -P
Good for quick dev/testing when you do not care which port you get. Bad for production — clients cannot know the port upfront. Also still binds to 0.0.0.0 by default.
-P publishes ALL EXPOSE'd ports to random host ports.
Ephemeral range (~49153+). Find them with docker port.
