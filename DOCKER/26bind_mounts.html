THE SYNTAX
-v FLAG vs --mount vs COMPOSE
ALL THREE FORMS REFERENCE
FORM 1 — -v shorthand (most common)
docker run \
  -v $(pwd)/src:/app/src \
  node:18-slim node index.js
HOST path : CONTAINER path
must use absolute path on host
FORM 2 — --mount verbose (explicit)
docker run \
  --mount type=bind,\
  source=$(pwd)/src,\
  target=/app/src \
  node:18-slim node index.js
clearer, safer — errors on missing path
FORM 3 — Docker Compose (best for dev)
services:
  app:
    image: node:18-slim
    volumes:
      - ./src:/app/src
relative paths work in compose ✓
🔒 READ-ONLY BIND MOUNT
-v $(pwd)/config:/app/config:ro
Container can read but NOT write to host.
Safer for config files and secrets.
-v is quick. --mount is explicit. Compose is cleanest.
Add :ro for read-only — safer for config injection.

GOTCHAS & GUIDE
WHAT CAN GO WRONG + WHEN TO USE
FINAL GUIDE CORRECT ✓
⚠ COMMON GOTCHAS
✗
Overwrites container dir — mounting to /app/node_modules wipes what was installed in the image
✗
Permissions mismatch — container user ≠ host user → can't write files
✗
Relative paths in -v — fails silently. Always use $(pwd) or absolute path
!
Slow on macOS/Windows — bind mounts use osxfs/WSL2 — can be slow on huge dirs
⚡ THE node_modules TRICK
volumes:
  - ./src:/app/src
  - /app/node_modules ← anonymous vol
Anonymous volume on /app/node_modules
prevents host from overwriting image deps.
USE IT FOR
✓ Local dev
✓ Hot reload
✓ Config inject
✓ Sharing logs
✓ Test fixtures
AVOID IN
✗ Production
✗ CI image builds
✗ Shared volumes
✗ Secrets files
✗ Cross-OS CI
BIND MOUNT vs NAMED VOLUME
host controls path bind mount
docker manages location named vol
dev workflow bind mount
production database named vol
Bind mount = dev only. Named volume = prod state.
Anonymous vol on node_modules prevents overwrite bugs.
