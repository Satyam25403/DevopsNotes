THE COMMANDS
CREATE · MOUNT · INSPECT · REMOVE
VOLUME COMMANDS REFERENCE
CREATE a named volume
docker volume create pgdata
pgdata
# or omit — Docker auto-creates on run
MOUNT volume into a container
docker run -d \
  -v pgdata:/var/lib/postgresql/data \
  --name postgres postgres:16
LIST & INSPECT volumes
docker volume ls
docker volume inspect pgdata
Mountpoint: /var/lib/docker/volumes/pgdata/_data
REMOVE a volume (explicit, irreversible)
docker volume rm pgdata
docker volume prune # remove all unused
⚠ data is permanently deleted
💡 MODERN --mount SYNTAX
docker run \
  --mount type=volume,\
  source=pgdata,\
  target=/var/lib/postgresql/data \
  postgres:16
More explicit. Preferred in new Dockerfiles.
docker volume create → run -v name:path.
Volume rm is explicit — data won't vanish by accident.

VOLUME TYPES
NAMED · BIND MOUNT · TMPFS
FULL GUIDE PICK ONE ✓
📦 NAMED VOLUME
-v pgdata:/var/lib/postgresql/data
Managed by Docker. Stored in Docker's own area.
Survives container removal. Portable between containers.
USE FOR: databases, app state, anything that must persist in prod.
📂 BIND MOUNT
-v /host/path:/container/path
Maps a host directory directly into the container.
Changes on host = instantly visible inside container.
USE FOR: local dev — live reload, config injection, sharing source code.
⚡ TMPFS MOUNT
--tmpfs /run:size=100m
Stored in host memory only. Never written to disk.
Fastest option. Disappears when container stops.
USE FOR: secrets, session tokens, scratch space — sensitive + ephemeral.
QUICK DECISION GUIDE
Database / app state in prod named volume
Live code reload in dev bind mount
Secrets / temp scratch tmpfs
Nothing needs to persist no mount needed
Named = prod. Bind = dev. tmpfs = secrets.
Pick by what survives and where it lives.
