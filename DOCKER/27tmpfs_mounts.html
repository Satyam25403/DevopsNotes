THE SYNTAX
--tmpfs FLAG vs --mount vs COMPOSE
COMMANDS REFERENCE
FORM 1 — --tmpfs shorthand
docker run \
  --tmpfs /run/secrets:size=64m \
  my-app
path[:options] — comma separated
FORM 2 — --mount explicit (preferred)
docker run \
  --mount type=tmpfs,\
  destination=/run/secrets,\
  tmpfs-size=67108864 \
  my-app
FORM 3 — Docker Compose
services:
  app:
    tmpfs:
      - /run/secrets:size=64m
      - /tmp/scratch
USEFUL OPTIONS
size=64m cap at 64 MB — prevent RAM exhaustion
noexec block executing binaries from tmpfs
nosuid disable setuid bits — extra hardening
mode=1777 set filesystem permissions (octal)
HARDENED PRODUCTION EXAMPLE
docker run \
  --tmpfs /run/secrets:\
  size=32m,noexec,nosuid \
  my-app
32MB RAM cap + no exec + no setuid ✓
--tmpfs path:options or --mount type=tmpfs.
Always set size= to prevent runaway RAM usage.

✅ PERFECT FOR tmpfs
⚡
API keys, tokens, passwords — runtime secrets
⚡
JWT signing keys, OAuth tokens — short-lived creds
⚡
Session data, in-memory cache — ephemeral state
⚡
Scratch space, temp files — fast I/O, no disk
⚡
Compliance: data must not persist — GDPR, HIPAA
✗ NEVER USE tmpfs FOR
✗ Databases — data disappears on every restart
✗ Large files — RAM is expensive, disk is cheap
✗ Anything that must survive a restart
