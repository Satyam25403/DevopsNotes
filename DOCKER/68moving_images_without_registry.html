WHAT'S INSIDE THE .tar
save & load commands
# save single image
$ docker save myapp:v1 \
-o myapp.tar
# save multiple images into one tar
$ docker save myapp:v1 myapp:v2 \
-o myapp-both.tar
# load on destination host
$ docker load -i myapp.tar
Loaded image: myapp:v1
📡 PIPE TO SSH — NO DISK NEEDED
$ docker save myapp:v1 | \
ssh user@host "docker load"
streams tar over SSH directly — zero temp file
docker save preserves every layer, tag, history entry and config blob.
docker load restores a pixel-perfect copy — identical image ID on the other side.

📤 EXPORT & IMPORT
FLAT FILESYSTEM SNAPSHOT
EXPORT / IMPORT LOSES METADATA
EXPORT MERGES ALL LAYERS → ONE FLAT FS
export & import commands
# export a container's filesystem
$ docker export my_container \
> container.tar
# import as a brand new flat image
$ docker import container.tar \
myapp:flat
# add a CMD back (lost on export)
$ docker import container.tar \
myapp:flat -- /bin/sh
🔎 WHEN IS export USEFUL?
▸ forensic snapshot of a running container
▸ extract files: tar -xf container.tar etc/
▸ minimise image size (no layer overhead)
▸ not a replacement for docker save in CI/CD
docker export flattens all layers into one — like a snapshot of the live filesystem.
CMD, ENV, ENTRYPOINT are lost. You must add them back on docker import.
