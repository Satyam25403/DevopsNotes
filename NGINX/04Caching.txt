Caching in Nginx is a powerful way to boost performance, reduce backend load, and speed up content delivery. 
Whether you're serving static assets or proxying dynamic content, Nginx can cache responses and serve them directly to clients—no need to hit your backend every time.

⚙️ Basic Nginx Caching Setup
Here’s a minimal config to enable caching for proxied content:
http {
    proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m max_size=1g inactive=60m use_temp_path=off;

    server {
        listen 80;

        location / {
            proxy_cache my_cache;
            proxy_pass http://localhost:5000;  # Your backend (Flask, Express, etc.)
            proxy_cache_valid 200 302 10m;
            proxy_cache_valid 404 1m;
            add_header X-Cache-Status $upstream_cache_status;
        }
    }
}



🧠 Key Directives Explained
| proxy_cache_path | Defines where cached files are stored and how they're organized | 
| keys_zone=my_cache:10m | Allocates 10MB of shared memory for cache metadata | 
| max_size=1g | Limits total cache size to 1GB | 
| inactive=60m | Removes items not accessed for 60 minutes | 
| proxy_cache | Enables caching for a location using the defined zone | 
| proxy_cache_valid | Sets how long to cache responses based on status code | 
| add_header X-Cache-Status | Adds a header to show cache hit/miss status | 



🔍 Cache Status Header
You’ll see one of these in the response:
- MISS: Not cached yet
- HIT: Served from cache
- EXPIRED: Cache expired, fetched fresh
- BYPASS: Caching skipped due to config or headers
