Let’s get you rolling with Nginx load balancing—a powerful way to distribute traffic across multiple backend servers for better performance, fault tolerance, and scalability.

⚙️ Basic Load Balancing Setup (Round Robin)
http {
    upstream backend_servers {
        server 192.168.1.101;
        server 192.168.1.102;
        server 192.168.1.103;
    }

    server {
        listen 80;
        location / {
            proxy_pass http://backend_servers;
        }
    }
}


🧠 What this does:
- Defines an upstream group of backend servers.
- Requests to / are distributed evenly (round-robin) across the servers.

📊 Load Balancing Methods
You can customize how traffic is distributed:
|  |  |  | 
|  |  |  | 
|  | least_conn; |  | 
|  | ip_hash; |  | 


Example with least_conn:
upstream backend_servers {
    least_conn;
    server 192.168.1.101;
    server 192.168.1.102;
}



🛡️ Health Checks (Manual or via Nginx Plus)
Open-source Nginx doesn’t support active health checks natively, but you can use passive checks or third-party modules. With Nginx Plus, you get built-in health monitoring and advanced algorithms.

🔁 Session Persistence (Sticky Sessions)
Use ip_hash to keep users on the same server:
upstream backend_servers {
    ip_hash;
    server 192.168.1.101;
    server 192.168.1.102;
}
