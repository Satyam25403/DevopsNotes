SERVER SIDE: SYN_RCVD
Between rcv SYN and rcv final ACK, the server holds the socket in SYN_RCVD. This is stored in the SYN backlog queue.
Too many SYN_RCVD = SYN flood (see scene 3).
TCP FLAGS IN THIS EXCHANGE

SYN=1 ACK=1

Client: CLOSED → SYN_SENT → ESTABLISHED.
Server: LISTEN → SYN_RCVD → ESTABLISHED.

☠ SYN FLOOD — SYN_RCVD OVERFLOW
🖥

Server replies SYN-ACK, waits for ACK that never arrives.
SYN backlog fills → legit connections refused (ECONNREFUSED)

⏱ TIME_WAIT — NOT A BUG
⏲
2×MSL countdown (≈60s)
0s30s60s ✓
After 4-way close, initiating side holds state 2×MSL.
MSL = Maximum Segment Lifetime ≈ 30s → 2×MSL = 60s.
Purpose: absorb delayed/duplicate packets from old connection.
10,000 TIME_WAIT entries = normal for busy server.

Remote sent FIN. Your app received it but hasn't called close().

Many CLOSE_WAIT = application bug, not kernel bug.
