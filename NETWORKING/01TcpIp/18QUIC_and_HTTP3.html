⚠ 0-RTT REPLAY ATTACK RISK
0-RTT data is sent before server authenticates client.
Attacker can replay 0-RTT packets to duplicate requests.
Rule: 0-RTT requests MUST be idempotent (GET, not POST).
Server must deduplicate or reject non-idempotent 0-RTT.
HOW 0-RTT WORKS
First visit: full handshake → server sends session ticket (PSK).
Second visit: client sends PSK + data in first packet.
Server recognises PSK → decrypts data immediately.
No round-trip needed for crypto setup.
QUIC has TLS 1.3 baked in — no separate shake.
0-RTT resume: send data before server acks.
0-RTT is replayable — only use for GET/HEAD.
