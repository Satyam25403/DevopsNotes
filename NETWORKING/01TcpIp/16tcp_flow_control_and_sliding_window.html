HOW rwnd WORKS
Every TCP ACK carries a Window field (16-bit).
Receiver says: "I have this many bytes free."
Sender MUST NOT have more than rwnd bytes
unacknowledged in flight at any time.
INSIDE EVERY ACK SEGMENT
ACK=5001  WIN=32768  ← rwnd
ACK=5001  WIN=8192   ← buffer filling
ACK=5001  WIN=0      ← ZERO WINDOW!
WINDOW SHRINKS AS BUFFER FILLS
full▶ time ▶ZERO WIN
Receiver advertises free buffer space.
Sender must respect this limit — always.
Window=0 → sender must stop immediately.

SLIDING WINDOW MECHANISM
As ACKs arrive, left edge slides right →
New segments enter the window from right.
Sender always fills up to min(rwnd, cwnd).
cwnd = congestion window (separate control)
Window slides right as ACKs arrive.
Sender keeps pipeline full up to rwnd.
min(rwnd, cwnd) is the actual send limit.

ROOT CAUSES OF ZERO WINDOW
Slow app not reading socket — backpressure propagates to sender
Small socket buffer (SO_RCVBUF) — tune via sysctl
High latency link — buffer fills before ACKs return
TUNE SOCKET BUFFERS
# max recv buffer
sysctl net.core.rmem_max=134217728

# auto-tune buffers
sysctl net.ipv4.tcp_rmem="4096 87380 134217728"
