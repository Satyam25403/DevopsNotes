① SYN SCAN DETECTION
tcp.flags.syn==1 && tcp.flags.ack==0
captures every SYN-only packet — connection initiations.
burst from one source IP = port scan or SYN flood.
🔍 USE CASE: nmap -sS (stealth scan) detection, DDoS triage
② XMAS SCAN
tcp.flags==0x029
FIN + PSH + URG all set simultaneously — never legitimate.
used by nmap -sX to fingerprint closed vs open ports.
🔍 USE CASE: hostile reconnaissance, evasion attempts
③ NULL SCAN
tcp.flags==0x000
all TCP flags cleared — never occurs in normal traffic.
used to evade stateless firewalls and IDS/IPS rules.
🔍 USE CASE: firewall evasion detection, IDS bypass attempts
④ RST STORM — SCAN RESPONSE PATTERN
tcp.flags.reset==1
high RST volume from target = many closed ports being probed.
combine with source filter to confirm scanner IP.
🔍 USE CASE: confirm port scan victim, measure scan scope
tcp.flags.syn==1 && tcp.flags.ack==0
SYN-only = connection attempt with no prior handshake.
100+ in 1s from one host = port scan. alert immediately.

① HTTP CREDENTIAL SEARCH
http contains "password"
matches any HTTP packet with "password" in payload.
catches login forms, config uploads, API key leaks over HTTP.
🔍 USE CASE: internal audit for unencrypted auth, forensics
② FTP / TELNET PASS COMMAND
tcp contains "PASS"
FTP sends "PASS <password>" in plaintext. Telnet too.
any result here = credentials transmitted cleartext.
🔍 USE CASE: legacy protocol audit, FTP server security review
③ HTTP POST — FORM SUBMISSIONS
http.request.method == "POST"
POST requests carry form data — login fields, search queries,
file uploads. over HTTP (not HTTPS) all payload is readable.
🔍 USE CASE: HTTP site audit, credential exposure during IR
④ HTTP BASIC AUTH (BASE64)
http.authbasic
HTTP Basic Auth sends Base64(user:pass) in every request header.
not encrypted — trivially decoded. still used on printers, NAS.
🔍 USE CASE: legacy device audit, finding exposed admin panels
http contains "password" || tcp contains "PASS"
any result = credential exposed in cleartext on the wire.
in 2025 this still happens on internal networks. audit first.

① DNS TUNNELING — LONG QUERIES
dns.qry.name.len > 40
normal DNS hostnames are short (15–30 chars).
DNS tunneling encodes data in subdomains → very long names.
tools like dnscat2, iodine generate queries like
"aGVsbG8gd29ybGQ.evil.com" (base64 data).
🔍 USE CASE: C2 exfil detection, firewall bypass identification
② DNS BEACONING — HIGH FREQUENCY
dns && ip.src == 192.168.1.50
combine with Statistics → IO Graph to visualize query rate.
regular interval queries (every 30s, 60s) = C2 heartbeat.
malware "checks in" via DNS to avoid IDS/firewall rules.
🔍 USE CASE: Cobalt Strike beacon, RAT C2 channel detection
③ HTTP C2 — BEACON INTERVALS
http.request && http.user_agent contains "Mozilla/4.0"
outdated User-Agent strings are a Cobalt Strike default.
regular outbound GETs to same external host = beacon.
check: Statistics → Conversations for interval patterns.
🔍 USE CASE: Cobalt Strike default profile detection
④ NON-STANDARD PORTS
tcp.port != 80 && tcp.port != 443 && tcp.port != 53
C2 frameworks often use unusual ports to blend or evade.
filter out known-good ports → inspect what remains.
common C2 ports: 4444, 8080, 1234, 31337.
🔍 USE CASE: RAT detection, reverse shell hunting, pivot channels
dns.qry.name.len > 40 → likely DNS tunneling
legitimate DNS names rarely exceed 30 chars. data-over-DNS
encodes payloads in subdomains. look for base64 patterns.

to extract files transferred over HTTP from pcap.
