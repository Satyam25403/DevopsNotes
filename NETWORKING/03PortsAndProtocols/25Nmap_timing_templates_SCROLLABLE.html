▸ THE CORE TRADEOFF
Timing controls the inter-probe delay and
parallel probe limits. Slower = harder to flag
as a scan. Faster = IDS triggers, missed ports
on lossy networks, dropped SYNs.

STEALTHY ZONE
T0 PARANOID · T1 SNEAKY · T2 POLITE
T0 / T1 / T2 REAL ENGAGE
-T0 PARANOID 5 MIN / PROBE
Serialized probes — one at a time, 5 minutes apart.
Virtually undetectable by any IDS/IPS signature.
A full port scan takes days. Use only on high-value,
heavily monitored targets where time is not a factor.
nmap -T0 -p22,80,443 target ← small port set only
-T1 SNEAKY 15s / PROBE
Still serialized, 15 seconds per probe. Stays under
most IDS thresholds that trigger on burst frequency.
Practical for sensitive or monitored targets where
you can wait hours for a scan to complete.
nmap -T1 -sS target ← hours for full scan, very quiet
-T2 POLITE 0.4s / PROBE
The sweet spot for real engagements. Parallel probes
but with enough delay to avoid triggering rate-based
IDS rules. Respects production bandwidth — won't
saturate links or cause packet drops.
nmap -T2 -sV -sC target ← 20-40min, usable results

NOISY ZONE
T3 DEFAULT · T4 AGGRO · T5 INSANE
T3 / T4 / T5 LAB/CTF ONLY
-T3 NORMAL DEFAULT
No explicit flag = T3. Parallel probes with no intentional
delay. Fine for CTF or isolated lab networks where
detection doesn't matter. Triggers most IDS signatures
trivially — SYN scan pattern is unmistakable at this rate.
nmap target ← implicit -T3, fine for HackTheBox/TryHackMe
-T4 AGGRESSIVE IDS BAIT
Assumes fast, reliable network. Max parallelism, very short
timeouts. Will absolutely fire IDS alerts on any monitored
network. Also starts missing ports on networks with any
congestion — fast timeouts = false negatives.
nmap -T4 -A target ← common tutorial default — dangerous on real targets
-T5 INSANE DO NOT USE
Sacrifices accuracy for raw speed. Timeouts so short that
packets are dropped before responses arrive — open ports
show as filtered. Instantly detectable. No legitimate
use outside an isolated, disposable lab machine.
nmap -T5 target ← library screaming — misses ports, instant IDS alert

T4/T5 are the "tutorial defaults" — seen everywhere, wrong for real work.
T5 misses open ports. Speed beyond T3 sacrifices accuracy, not just stealth.

SCENARIO → TIMING DECISION
T0
Heavily monitored target, weeks-long engagement, small port set, IDS evasion is primary goal
T1
Red team, scoping a sensitive network, SOC is active — time matters less than not getting caught
T2
Default for all real engagements. Pentest, bug bounty, prod recon, client networks, anything outside your own lab
T3
CTF, HackTheBox, TryHackMe, your own isolated VM — fast results, detection irrelevant
T4
CTF or when you need faster results in a lab — never on anything you don't own, misses ports on any real network
T5
Almost never justified. Disposable lab only. Expect missed ports and instant detection on anything real
▸ PRO TIPS
--min-rate / --max-rate give finer control than -T
--scan-delay sets exact inter-probe delay in ms
Combine with -f (fragment) or --data-length for
deeper IDS evasion alongside T0/T1 timing
-T2 --max-retries 2 is a solid all-round combo
▸ #1 MISTAKE IN THE WILD
nmap -T4 -A -sV target_range ← tutorials do this
-T4 on a client network = guaranteed IDS alert + disrupted services.
Fix: nmap -T2 -sS -sV --open target
Timing is the first OPSEC decision in any scan — make it deliberately.
Real engagement = -T2 minimum. No exceptions. CTF = whatever you want.
