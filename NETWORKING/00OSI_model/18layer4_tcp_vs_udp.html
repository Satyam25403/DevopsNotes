CONGESTION CONTROL
Slow-start, AIMD. TCP backs off when network is congested. Plays nice.
01
SYN → SYN-ACK → ACK. No data until the handshake completes. Adds 1 round-trip latency upfront. That's why HTTPS feels slightly slower on first connect — worth it for a bank.
02
If a segment is lost, TCP retransmits it. Receiver won't pass data to the app until all prior segments arrive. This is why TCP feels "laggy" on packet loss — it waits.
TCP OVERHEAD
20-byte header + handshake + ACKs = reliability tax
Every guarantee costs something. TCP's reliability features add latency, CPU, and bandwidth overhead. For financial data, that's worth it. For a 30fps game, it isn't.

UDP 8B vs TCP 20B
01
No connection setup. Just send the datagram. No handshake overhead, no waiting for ACK, no retransmit. Each packet is independent — ideal when latest data beats complete data.
02
In a video call, a dropped frame is fine — you'll get the next one 33ms later. TCP would freeze everything waiting for the retransmit. UDP lets the stream continue with the occasional glitch.
03
QUIC (HTTP/3) is UDP underneath but adds its own reliability. Best of both worlds: UDP's speed, custom reliability logic. Google built it. Now the default for most Chrome connections.
UDP PHILOSOPHY
"Send and forget. If it arrives, great."
UDP is the foundation for anything that needs raw speed: DNS (one small query/reply), live video, online games (position updates), VoIP, and QUIC/HTTP3 which layers its own logic on top.

Ephemeral (client) ports
01
A port is a 16-bit number (0–65535) that tells the OS which process should receive the packet. Multiple servers on one IP — each on a different port. Like apartment numbers in a building.
02
Ports 0–1023 are well-known ports (root required on Linux). 1024–49151 are registered. 49152–65535 are ephemeral — used as temporary source ports for client connections.
PORTS
IP gets to the machine. Port gets to the app.
A socket = IP address + port + protocol. A server can handle thousands of simultaneous TCP connections because each has a unique (src-IP, src-port, dst-IP, dst-port) tuple.

THE DECISION RULE
Need every byte? → TCP
Order matters? → TCP
Speed > completeness? → UDP
Latest data > all data? → UDP
Need custom reliability? → UDP + DIY (QUIC)
INTERVIEW ANSWER
TCP = reliability. UDP = speed. Trade-off by design.
If asked "TCP or UDP for X" — think: can the application tolerate dropped packets? If yes → UDP. If correctness is mandatory → TCP. QUIC is the modern answer that blurs the line.
