HOW BCP38 WORKS
ISP checks: does the source IP make sense coming from this customer port?

Customer assigned 203.0.113.0/24. Packet arrives with src=8.8.8.8 (Google). IMPOSSIBLE → DROP.

This kills amplification DDoS attacks at the source — the attacker can't spoof victim IPs to trigger reflection.
KILLS AMPLIFICATION DROPS SPOOFED PKT
ALSO: RFC1918 BLOCKING
Public-facing interfaces should never see packets with private source IPs (10.x, 172.16.x, 192.168.x). Drop them at ingress — they're either spoofed or misconfigured.

ROA — ROUTE ORIGIN AUTHORISATION
A signed certificate that says: "AS64496 is authorised to announce 203.0.113.0/24."

Stored in the global RPKI repository. Routers query it via an RPKI validator before accepting BGP routes.
ROA: prefix=203.0.113.0/24
     maxLength=24
     origin=AS64496
     signature=✓ VALID
VALID
ROA exists, AS and prefix match. Accept route.
INVALID
ROA exists but AS doesn't match. DROP — hijack attempt.
NOT FOUND
No ROA. Accept (for now) — adoption not 100%.
RPKI:
ROA = signed proof you own the prefix.
INVALID routes dropped. Kills BGP hijacking.

IKE HANDSHAKE — HOW TUNNELS FORM
IKEv2 (UDP 500 / 4500) negotiates the SA:

Phase 1: Authenticate peers (PSK or PKI cert) + derive master key via DH.
Phase 2: Negotiate encryption alg (AES-256), auth (SHA-256), lifetime.
Done: Bidirectional ESP tunnel active. All L3 traffic encrypted.
IPsec:
Encrypt + auth every IP packet in transit.
ESP = VPNs. IKEv2 = tunnel negotiation.
