SMURF ATTACK — SPOOFING + AMPLIFICATION
01
The IPv4 header has a source IP field with no signature or verification. Raw sockets (available to root/admin) let you write any value there. The router forwards it anyway.
02
Smurf attack: spoof victim's IP as source, send ICMP echo to broadcast address. Every host on the network replies to the victim. 1 packet becomes 1000. DDoS amplification.
03
BCP38 (ingress filtering): ISPs should drop packets whose source IP doesn't belong to the customer's address space. Prevents spoofing at origin. Most ISPs now implement this — but not all.
IP SPOOFING

IPv4 was designed when trust was assumed. A raw socket on any Linux machine can forge any source IP. BCP38 at ISP level is the only real prevention.

HOW BGP ROUTING WORKS
Routers exchange BGP UPDATE messages: "I can reach prefix X.X.X.X/N via path [AS1, AS2, AS3]". All BGP peers accept this by default. Most specific prefix wins.
HOW HIJACK HAPPENS
Attacker announces a more specific prefix (e.g. /24 instead of /22) for IP space they don't own. Routers prefer more specific → traffic redirects. No password, no signature required.
01
BGP (Border Gateway Protocol) is how internet routers share routing information between Autonomous Systems (AS). Each AS is an ISP, cloud provider, or large network. ~73,000 ASes today.
02
BGP has zero origin authentication. Any AS can announce any prefix. Routers accept the most-specific matching prefix. Announce /24 for someone's /22 → you win their traffic.
03
2010 China Telecom: AS23724 announced 37,000+ more-specific prefixes including US government and military ranges. Traffic silently detoured through China for 18 minutes. Classified content at risk.
BGP TRUST MODEL
Every AS trusts every other AS by default
BGP was designed for 1989 internet — a few hundred cooperating universities. At 73,000 ASes, one misconfigured or malicious router can redirect global traffic in seconds.

Major clouds (AWS, GCP, Azure, Cloudflare) fully RPKI-signed. But ~55% of prefixes still unprotected. Full protection requires universal adoption.
01
RPKI (Resource PKI) lets IP prefix owners create a ROA (Route Origin Authorization) — a cryptographically signed record saying "AS15169 is authorized to announce 8.8.8.0/24".
02
Routers with RPKI validation reject BGP updates from unauthorized ASes. China Telecom's fake announcement would be dropped — it doesn't match the ROA signed by ARIN.
03
Combined with BCP38 (IP spoofing fix at ISP) and RPKI (BGP hijacking fix), most Layer 3 attacks become impractical. But adoption is still incomplete — the internet is only as safe as its weakest AS.
RPKI
Cryptographic proof that AS owns the prefix
Cloudflare, Amazon, Google all publish ROAs. If your ISP validates them, a China Telecom-style hijack of their prefixes is impossible — the route would be marked INVALID and dropped.
