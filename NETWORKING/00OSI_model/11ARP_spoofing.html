HOW TO DEFEND
DAI · STATIC ARP · DETECTION · HTTPS
DEFEND MITIGATIONS
LAYERED DEFENSES AGAINST ARP SPOOFING
🛡
DYNAMIC ARP INSPECTION (DAI)
Cisco / Juniper switch feature. Switch maintains a DHCP snooping table mapping each port → IP → MAC. Any ARP reply that doesn't match is dropped at the switch port. Attacker's fake replies never reach victims.
Config: ip arp inspection vlan 10 · Requires DHCP snooping enabled first
📌
STATIC ARP ENTRIES
Manually pin critical IP→MAC mappings. Static entries cannot be overwritten by ARP replies. Practical for gateways on critical servers.
arp -s 192.168.1.1 dd:ee:ff:44:55:66 (Linux/macOS)
🔍
DETECTION: arpwatch / XarpPlus
Monitors ARP traffic. Alerts on MAC address changes for existing IPs — the exact signature of ARP poisoning. Also look for duplicate IP alerts in Wireshark.
Wireshark filter: arp.duplicate-address-detected
🔒
HTTPS + HSTS + VPN
Even with MITM, TLS encryption prevents content reading. HSTS prevents SSL stripping. A VPN tunnels above L2 — ARP poisoning can intercept the tunnel but can't decrypt it.
Best combo: DAI at switch + HTTPS everywhere + VPN on untrusted networks
⚠ WHAT DOESN'T HELP
Firewalls · Antivirus · IDS/IPS · Strong passwords · Incognito mode
All operate above L2. ARP spoofing happens before any of these see the traffic.
KEY TAKEAWAY
DAI at the switch is the only real fix
All other defenses are workarounds. DAI validates ARP replies against ground-truth DHCP records at the switch level — the only point where the lie can be caught.
