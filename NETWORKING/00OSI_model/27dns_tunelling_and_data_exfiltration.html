HOW DATA IS ENCODED
Step 1: secret_document.pdf → read raw bytes
Step 2: base64 encode → c2VjcmV0X2RvY3Vt...
Step 3: chunk into ≤63 char labels (DNS limit)
Step 4: send c2VjcmV0.X2RvY3Vt.chunk3.tunnel.attacker.com
Step 5: NS server logs each query subdomain → reassembles file
01
The attacker controls a nameserver for their own domain (e.g. attacker.com). Every DNS query for *.attacker.com flows to their NS server. The NS server is their C2.
02
DNS queries travel through the ISP's recursive resolver to the attacker's NS. The firewall sees only DNS port 53 — it doesn't inspect subdomain content. Data exfiltrated silently.
WHY IT WORKS
DNS is recursive — queries reach attacker's NS by design
DNS delegation means any query for attacker.com flows to their nameserver globally — through every resolver, through every corporate firewall. No direct connection needed.

TOOL COMPARISON
iodine
Full IP tunnel over DNS. Supports TCP/UDP. Bandwidth ~1Mbit. Used for persistent access and data exfil.
dnscat2
C2 shell over DNS. Encrypted. Multiple sessions. Command execution, file transfer. APT favorite.
01
iodine creates a full IP tunnel over DNS. Once connected, attacker can SSH into the victim, browse their intranet, and exfiltrate files — all traffic disguised as DNS queries.
02
dnscat2 is purpose-built for C2 over DNS. Encrypted sessions. Multiple command shells. Runs on Windows, Linux, macOS. Used in real APT campaigns (OilRig, APT29 tooling).
03
Bandwidth is low (~10–500 KB/s) but sufficient for: credentials, SSH keys, source code, small databases, shell commands. APTs use it for persistent low-and-slow exfiltration over weeks.
C2 OVER DNS
Full shell access through any DNS-permissive firewall
Nation-state groups use DNS tunneling when all other channels are blocked. If a machine can resolve DNS, it can be a C2 node. No direct inbound connection needed.

DETECTION SIGNALS
ANOMALOUS QUERY LENGTH · FREQUENCY · SIEM RULES
DETECTION SIEM RULES
NORMAL DNS vs TUNNEL DNS
NORMAL
Queries: ~30/hr
Length: 10–40 chars
Domains: known TLDs
Records: A, AAAA, MX
Pattern: random times
TUNNEL ⚠
Queries: 1000s/min
Length: 100–200 chars
Domains: 1 strange domain
Records: TXT, NULL types
Pattern: rapid bursts
SIEM DETECTION RULES
HIGH · DNS TUNNEL INDICATOR
Query length >100 chars from single host. Triggered: workstation-14 querying *.attacker.com. 4,200 queries in 60s.
MED · ANOMALOUS DNS VOLUME
Single source IP: 10.1.1.45 made 5,000 DNS queries in 5 minutes to same domain. Baseline: 80/hr.
HIGH · TXT RECORD ABUSE
TXT record queries for non-email domain. TXT records are primary C2 response channel in dnscat2.
LOW · HIGH ENTROPY SUBDOMAIN
Base64/hex patterns in subdomain (random-looking strings 32+ chars). Possible encoding detected.
01
Normal workstations make ~30–100 DNS queries/hour. DNS tunneling generates thousands per minute. Volume anomaly detection in SIEM catches this. Baseline normal, alert on deviation.
02
Query length is the strongest signal. Normal FQDN: 20–40 chars. Tunnel queries: 100–200 chars of base64. Write a SIEM rule: dns.query.length > 100 → alert HIGH.
03
Shannon entropy of subdomain labels. "aGVsbG8gd29ybGQ" has high entropy (looks random). "mail.google.com" has low entropy. High entropy + unusual domain = tunnel indicator. Tools: Zeek, Suricata DNS scripts.
DETECTION STRATEGY
Volume + length + entropy. Three signals, one alert.
DNS logging is often disabled by default. Enable it first. Then: SIEM rules on query length >100, volume >1000/min/host, TXT queries to unknown domains, and high-entropy subdomains.

DEFENSES & MITIGATIONS
DNS FIREWALL · LOGGING · RPZ · INSPECTION
DEFEND MITIGATIONS
LAYERED DNS SECURITY CONTROLS
🔒
FORCE DNS THROUGH INTERNAL RESOLVER
Block direct UDP/TCP port 53 to external IPs. Force all DNS through your internal resolver. Internal resolver can log, filter, and block malicious domains. Attacker can't bypass your resolver.
iptables: FORWARD -p udp --dport 53 ! -d [resolver] -j DROP
📋
DNS RESPONSE POLICY ZONES (RPZ)
Block known malicious domains at resolver level. Subscribe to threat intel feeds (ESET, Cloudflare Gateway, Cisco Umbrella). Any query to blocklisted C2 domains returns NXDOMAIN. Blocks iodine/dnscat2 before tunnel forms.
📊
FULL DNS LOGGING + SIEM
Enable query logging on all resolvers. Forward to SIEM. Rules: query_length > 100, queries/min/host > 500, TXT records to unknown domains. Zeek has built-in DNS tunnel scripts.
🔭
DNS INSPECTION + DPI
Deep packet inspection on DNS traffic. Detect base64/hex patterns in subdomains. Tools: Suricata with dns-tunnel rules, Palo Alto DNS Security, Cisco Umbrella. Rate-limit TXT and NULL record responses.
THE FUNDAMENTAL TENSION
Problem: You can't block DNS entirely
Reality: Only detect + alert on anomalies
Best defense: Internal resolver + RPZ + logging
Nuclear option: DNS-over-HTTPS to known resolver
KEY INSIGHT
You can't block DNS. You must monitor it.
Force traffic through your resolver, log everything, and alert on anomalies. Cloudflare Gateway and Cisco Umbrella include DNS tunnel detection as a feature. Enable DNS logging today — it's off by default on most resolvers.
