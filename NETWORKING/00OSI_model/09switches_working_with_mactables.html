THE SECRET WEAPON
The switch maintains a CAM table (Content Addressable Memory) that maps every MAC address it has seen to the port it came in on. It uses this table to forward frames only where they need to go.

⚠ THE PROBLEMS WITH HUBS
Privacy: PC-B and PC-C receive PC-A's frame. A hacker with a hub can see all traffic — passive sniffing attack.

Performance: Only one device can transmit at a time. All devices share bandwidth. 100 Mbps hub ÷ 4 devices = 25 Mbps each.
HUB RULE:
Frame in on port 1 → out on ALL ports.
No exceptions. No filtering. Just noise.

HOW THE SWITCH LEARNS
Step 1: Frame arrives on Port 1 from PC-A
Step 2: Read SOURCE MAC → AA:AA:AA:AA
Step 3: Record "AA:AA → Port 1" in CAM table
Step 4: Repeat for every device that sends
Note: Entries age out after ~300 seconds if unused
LEARNING PROCESS:
Source MAC + arrival port → CAM table.
Switch learns passively. No config needed.

DST MAC is in the CAM table. Forward to Port 4 only. PC-B and PC-C see nothing. Most traffic is unicast.
BROADCAST — DST MAC = FF:FF:FF:FF:FF:FF
PC-A
→ 🔀 → ALL
PC-B
PC-C
PC-D
DST is broadcast address. Switch floods all ports (except source). ARP requests use this. Contained within broadcast domain (VLAN).
UNKNOWN UNICAST — DST MAC NOT IN TABLE
If the switch hasn't seen a MAC address yet, it floods all ports — just like a hub — until it learns. This is normal startup behaviour.
FLOOD THEN LEARN TEMPORARY ONLY
⚠ MAC TABLE ATTACK — CAM FLOODING
Attacker sends thousands of fake frames with random MACs. Switch fills its CAM table (limited size). When full, switch behaves like a hub — floods all ports. Attacker can now sniff all traffic. Mitigated by port security (limit MACs per port).
THREE MODES:
Unicast → 1 port. Broadcast → all ports.
Unknown unicast → flood until learned.
