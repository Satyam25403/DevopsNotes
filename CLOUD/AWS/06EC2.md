# Amazon EC2 (Elastic Compute Cloud)

Amazon EC2 provides scalable, resizable virtual servers (instances) in the cloud. It's the backbone of AWS compute — used for everything from hosting web apps to running ML training jobs.

---

## Core Concepts

### Instances
A virtual server running in AWS. You choose the OS (Linux/Windows), CPU, memory, storage, and networking. Instances are billed by the second (minimum 60 seconds).

### AMI (Amazon Machine Image)
A pre-configured template used to launch instances. Contains the OS, application server, and any pre-installed software. AWS provides official AMIs (Amazon Linux, Ubuntu, Windows Server), and you can create custom AMIs from running instances.

### Instance Types
Different hardware profiles for different workloads:

| Family | Optimized For | Example |
|--------|--------------|---------|
| t3, t4g | Burstable general-purpose | t3.micro (free tier) |
| m6i, m7g | Balanced general-purpose | m6i.large |
| c6i, c7g | Compute-intensive | c6i.xlarge |
| r6i | Memory-intensive | r6i.2xlarge |
| p3, p4 | GPU / ML training | p3.2xlarge |
| i3, i4 | Storage-optimized | i3.large |

### Key Pairs
Used for SSH authentication. AWS stores the public key; you keep the private key (`.pem` file). **Download and save it immediately — you cannot retrieve it again.**

### Security Groups
Virtual firewalls controlling inbound and outbound traffic. See the Security Groups section below.

### Elastic IP (EIP)
A static public IPv4 address. By default, EC2 instances get a new public IP every time they stop/start. Attach an Elastic IP to keep a consistent address.

---

## Launching an Instance

1. Choose an **AMI** (e.g., Ubuntu 24.04 LTS)
2. Choose an **instance type** (e.g., `t2.micro` for free tier)
3. Configure networking (VPC, subnet, security group)
4. Create or select a **key pair**
5. Launch

## Connecting to an Instance

### Using EC2 Instance Connect (browser-based)
In the AWS Console, select your instance → **Connect** → **EC2 Instance Connect**. Opens a terminal in the browser — no key file needed.

### Using SSH (from your local machine)
```bash
# Restrict key file permissions (required)
chmod 400 yourkey.pem

# Connect using public DNS
ssh -i "yourkey.pem" ubuntu@<ec2-public-dns>

# Or using IP address directly
ssh -i "yourkey.pem" ubuntu@<ec2-public-ip>
```

> Default usernames: `ubuntu` for Ubuntu AMIs, `ec2-user` for Amazon Linux, `admin` for Debian.

## Copying Files to/from EC2

### SCP (Secure Copy)
```bash
# Upload a file
scp -i "yourkey.pem" myfile.txt ubuntu@<ec2-ip>:~/

# Upload a folder recursively
scp -i "yourkey.pem" -r ./my-project ubuntu@<ec2-ip>:~/my-project

# Download a file from EC2
scp -i "yourkey.pem" ubuntu@<ec2-ip>:~/output.log ./output.log
```

### Git
```bash
# On the EC2 instance, clone your repo
git clone https://github.com/youruser/your-repo.git
```

## Security Groups

Security groups act as virtual firewalls. Key points:
- **Inbound rules**: What traffic is allowed **in** (default: deny all).
- **Outbound rules**: What traffic is allowed **out** (default: allow all).
- **Stateful**: If inbound is allowed, the response is automatically allowed out.
- **No explicit deny**: You can only allow or not-allow — use Network ACLs for explicit denies.
- Multiple security groups can be attached to one instance; if **any** group allows the traffic, it's permitted.

**Common rules to configure:**
```
SSH        TCP  22    Your IP (0.0.0.0/0 is risky — lock to your IP)
HTTP       TCP  80    0.0.0.0/0
HTTPS      TCP  443   0.0.0.0/0
Custom App TCP  3000  0.0.0.0/0   (e.g., Node.js app)
```

> **Troubleshooting**: If your app is running but the browser infinitely loads, check that your security group allows TCP traffic on the app's port.

## VPC (Virtual Private Cloud)

A VPC is your own isolated slice of the AWS cloud. All EC2 instances live inside a VPC.

- **Subnets**: Subdivisions of a VPC. Public subnets have internet access via an Internet Gateway; private subnets are internal-only.
- **Route Tables**: Control where traffic is directed.
- **Internet Gateway (IGW)**: Allows communication between your VPC and the internet.
- **NAT Gateway**: Allows instances in private subnets to reach the internet (for updates, etc.) without being reachable from the internet.
- **Default VPC**: AWS creates one default VPC per region automatically.

## Running Processes After SSH Disconnect

By default, processes started in an SSH session are killed when the session ends.

### nohup (simple background process)
```bash
nohup python3 app.py > output.log 2>&1 &

# > output.log       : redirect stdout to log file
# 2>&1               : redirect stderr to same log file
# &                  : run in background

# View logs
tail -f output.log

# Check if running
ps aux | grep app.py
```

### Find and Kill a Background Process
```bash
# Find by name
ps aux | grep app.py
pgrep -f app.py

# Kill gracefully (SIGTERM)
kill <PID>

# Force kill (SIGKILL) — use if graceful kill doesn't work
kill -9 <PID>

# One-liner
kill $(pgrep -f app.py)
```

### systemd (recommended for production services)
For long-running services, use systemd instead of nohup — it handles restarts, logging, and boot-time startup:

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My Node.js App
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/my-app
ExecStart=/usr/bin/node app.js
Restart=always
RestartSec=5
Environment=NODE_ENV=production
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
# Enable and start
sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp

# Check status and logs
sudo systemctl status myapp
sudo journalctl -u myapp -f
```

## DNS, Reverse Proxy & HTTPS

### The Problem
Your app runs on `<ec2-ip>:3000`. Users can't remember IPs, and port numbers look unprofessional.

### Solution: DNS + Reverse Proxy

1. **Buy a domain** (e.g., from Route 53, Namecheap)
2. **Point DNS to your EC2 IP** (A record → EC2 Elastic IP)
3. **Install Nginx as a reverse proxy** to route traffic on port 80/443 to your app

```bash
sudo apt install nginx
sudo systemctl enable nginx
sudo systemctl start nginx
```

**Nginx config** (`/etc/nginx/sites-available/myapp`):
```nginx
server {
    listen 80;
    server_name myapp.com www.myapp.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/myapp /etc/nginx/sites-enabled/
sudo nginx -t        # test config
sudo systemctl reload nginx
```

### HTTPS with Let's Encrypt (Certbot)
```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d myapp.com -d www.myapp.com
# Certbot automatically edits the Nginx config and sets up auto-renewal
```

> Certbot auto-renews certificates via a cron job. Certificates expire every 90 days.

## EC2 Pricing Models

| Model | Use Case | Cost |
|-------|----------|------|
| **On-Demand** | Dev/test, unpredictable workloads | Highest (pay by second) |
| **Reserved** (1-3 yr) | Steady-state production workloads | Up to 72% cheaper than On-Demand |
| **Spot Instances** | Fault-tolerant, flexible workloads | Up to 90% cheaper — can be interrupted |
| **Savings Plans** | Flexible commitment across instance types | Up to 66% savings |

## Best Practices

- **Use IAM roles** (not access keys) on EC2 to access other AWS services.
- **Use Elastic IPs** if you need a stable IP address.
- **Use private subnets** for databases and internal services — only expose what needs to be public.
- **Enable CloudWatch monitoring** to track CPU, network, and disk metrics.
- **Take EBS snapshots** regularly for backup.
- **Use Auto Scaling + Load Balancer** for production apps that need high availability.
- **Restrict SSH access** in security groups to your IP only, not `0.0.0.0/0`.
- **Use SSM Session Manager** as an alternative to SSH — no open port 22 needed.
