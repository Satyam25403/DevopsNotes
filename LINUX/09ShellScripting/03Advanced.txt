# 1️⃣ Advanced File Handling (Beyond `-f`, `-d`)

## 🔹 File comparison
```sh
[ file1 -nt file2 ]   # file1 newer than file2
[ file1 -ot file2 ]   # file1 older than file2
```
Use case: **incremental backups**

## 🔹 Ownership & permissions
```sh
[ -O file.txt ]   # owned by current user
[ -G file.txt ]   # group-owned
```

## 🔹 Symlink checks
```sh
[ -L linkfile ]   # symbolic link
```
Important when dealing with:
* `/etc/alternatives`
* `/var/log` symlinks

## 🔹 Safe file creation (avoid overwrite)
```sh
set -o noclobber
echo "data" > file.txt   # fails if file exists
```

## 🔹 Atomic file write (VERY IMPORTANT)

Never do:
```sh
echo "data" > config.conf   # ❌ can corrupt
```

Correct way:
```sh
tmp=$(mktemp)
echo "data" > "$tmp"
mv "$tmp" config.conf
```
Used in:
* Config updates
* Deployments
* Secrets rotation

# 2️⃣ `set -e` — The TRUTH (very important)

## ❌ Misconception

> "`set -e` exits on any error"

❗ **Not always**

### ❌ It does NOT exit here:

```sh
set -e
if false; then
  echo "won't run"
fi
echo "still runs"
```

---

## ❌ It does NOT exit in:

```sh
false || true
```

---

## ✅ When it DOES exit:

```sh
false
cmd1 && cmd2   # if cmd1 fails
```

---

## ✅ Proper error handling pattern

```sh
set -euo pipefail
```

And explicitly handle failures:

```sh
command || {
  echo "Command failed"
  exit 1
}
```

---

## 🔹 Disable temporarily (advanced)
```sh
set +e
some_command_that_may_fail
set -e
```

# 3️⃣ Traps & Signals (REAL WORLD)

## 🔹 Common signals

| Signal | Meaning        |
| ------ | -------------- |
| INT    | Ctrl+C         |
| TERM   | kill           |
| EXIT   | script ends    |
| ERR    | command failed |

---

## 🔹 Cleanup on EXIT (MUST USE)
```sh
cleanup() {
  rm -f /tmp/file.$$
}
trap cleanup EXIT
```
✔ Runs on:
* Success
* Failure
* Ctrl+C

---

## 🔹 Debug error location

```sh
trap 'echo "Error at line $LINENO"' ERR
```

🔥 Interview-level answer.

# 4️⃣ Defensive Scripting (Professional Style)

## 🔹 Always quote variables

```sh
"$var"
```

Bad:

```sh
rm $file
```

Good:

```sh
rm -- "$file"
```

---

## 🔹 Validate inputs

```sh
[ "$#" -eq 2 ] || {
  echo "Usage: $0 src dest"
  exit 1
}
```

---

## 🔹 Absolute paths only (cron safe)

```sh
/bin/cp /bin/rm /usr/bin/awk
```

Cron has limited `$PATH`.

---

## 🔹 Use `readonly`

```sh
readonly CONFIG="/etc/app.conf"
```

Prevents accidental overwrite.

# 5️⃣ Idempotency (🔥 DevOps GOLD)

> **Running the script multiple times should give the same result**

---

## ❌ Non-idempotent

```sh
useradd appuser   # fails second time
```

---

## ✅ Idempotent

```sh
id appuser >/dev/null 2>&1 || useradd appuser
```

---

## 🔹 Directory creation

```sh
mkdir -p /opt/app
```

---

## 🔹 Package install

```sh
dpkg -l nginx >/dev/null 2>&1 || apt install -y nginx
```

---

# 6️⃣ Debugging Shell Scripts (Must Know)

## 🔹 Debug mode

```sh
set -x
```

Shows:

```sh
+ ls /tmp
+ rm file
```

---

## 🔹 Trace only a section

```sh
set -x
command1
command2
set +x
```

---

## 🔹 Dry run pattern

```sh
DRY_RUN=true

run() {
  if [ "$DRY_RUN" = true ]; then
    echo "DRY: $*"
  else
    "$@"
  fi
}

run rm file.txt
```

🔥 Used in infra scripts.

# 7️⃣ Mini Real-World Script (Production Quality)

```sh
#!/bin/sh
set -euo pipefail

LOG="/var/log/backup.log"
SRC="/etc"
DEST="/backup"

log() {
  echo "$(date '+%F %T') $*" >> "$LOG"
}

cleanup() {
  log "Script finished"
}
trap cleanup EXIT

[ -d "$DEST" ] || mkdir -p "$DEST"

tar -czf "$DEST/etc-$(date +%F).tar.gz" "$SRC"
log "Backup successful"
```

✔ Safe
✔ Logged
✔ Idempotent
✔ Crash-proof

# 🧠 Interview One-Liners (MEMORIZE)

* **Idempotency is critical in automation**
* **Always trap EXIT for cleanup**
* **Never trust user input**
* **Always quote variables**
