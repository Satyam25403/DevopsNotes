>uptime : system uptime

Interactive(process monitoring/CPU usage)
>top or htop                  :running processes
>top -p <pid>                 :monitor a particular processes
%CPU → CPU usage per process
us → user processes
sy → system/kernel
id → idle CPU
wa → IO wait (⚠️ very important)



Process snapshot(non-interactive)
>ps                           :processes running in current terminal
>ps -a                        :all processes 
>ps -p <pid>                  :info about a specific processes
>ps -ef --forest              :more organized and detailed along with parent processes, Very useful to debug orphan or zombie processes
>ps -u <username>             :processes available for a user
>ps aux                       :all processes detailed view(CPU, MEM, user, command)
>ps aux --sort=<field>        :- → descending order;no - → ascending order
common sort parameters %cpu, %mem, start_time, pid, user
>ps aux --sort=-%cpu,-%mem    : cpu first and then if tie? then by memory

instead of aux, use -eo(recommended in DevOps scripts)
>ps -eo pid,user,%cpu,%mem,cmd --sort=-%cpu | head



Process identification and Control
>pidof <processname>          : PID(s) of a running process ex: pidof nginx
>kill <pid>
>kill -9 <pid>                : forcekill a process(SIGKILL)
-15 for(SIGTERM) Graceful termination
>killall -9 <processname>     :kill all instances of process(ex:multiple chrome windows)
>pkill <processname>
>pgrep <processname>          :find pids by name



Process Priority(nice and renice):
setting priority means increasing or decreasing how much CPU time a process gets.
-20 → highest priority
 0  → default
19  → lowest priority
Higher nice = lower priority
>ps -o pid,ni,cmd                         :displays pid, nice value, command
>nice -n <value> <command>                :starts a command/process with associated priority
>renice -n <value> <pid>                  :changes priority of running process...needs root for making process more prioritized
>renice -n <value> -u <username>          :Changes the CPU priority (nice value) of all running processes owned by a specific user




Cron jobs(scheduled tasks):
a.One-Time jobs:
>sudo apt install at 
><some command> | at <hh:mm>              :schedule a one-time job...u can use as(| at now + <t> minute)
ex: echo "Hello kali" | at 8:04
>atq                                      :lists pending 'at' jobs; their jobid, execution time and owner
>atrm <jobid>                             :deletes a scheduled 'at' job
b.Recurring jobs:
Time fields (in same order) : minute(m) hour(h) day_of_month(dom) month(mon) day_of_week(dow) 
>crontab -l                               :lists current users cron jobs...reads from /var/spool/cron/crontabs/<username>
>crontab -e                               :opens a crontab editor to schedule recurring jobs
>crontab -r                               :deletes all cron jobs for that users...Dangerous
ex: 0 5 * * * tar -czf /var/backups/home.tgz /home
At 05:00 every day
Creates compressed backup of /home
Stores it at /var/backups/home.tgz
Meaning of time symbols:
| Symbol | Meaning         |
| ------ | --------------- |
| `*`    | Every value     |
| `*/5`  | Every 5 units   |
| `,`    | Multiple values |
| `-`    | Range           |
NOTE: if script is involved in a cronjob, it must be executable
>journalctl -u cron (or) >cat /var/log/syslog         :cronjob logs



System monioring and logging(journalctl, systemd, dmesg): observe system + kernel
Journal:journal of everything inside the system
>journalctl                                                       :all logs(kernel, service, system messages) sorted chronologically(old->new)
a modern replacement of /var/log/*              
>systemctl list-units --type=<unit>                              :lists all active systemd managed units of a particular type...shows only system level ones(not user apps like chrome)   
systemd manages different unit types such as services, sockets, targets, timers, mounts, and devices, each representing a specific system resource or behavior
| Unit Type | Purpose                   |
| --------- | ------------------------- |
| service   | Background services       |ex:docker,nginx
| socket    | Socket-activated services |listens on port or IPC sockert ex: ssh.socket, docker.socket
| target    | Grouping / runlevels      |logical grouping of units ex:multi-user.target, graphical.target
| device    | Hardware devices          |represents hardware devices ex:dev-sda.device
| mount     | Mounted filesystems       |equivalent to /etc/fstab ex:home.mount, var-log.mount
| automount | On-demand mounts          |
| path      | File/directory watchers   |triggers services ex:logrotate.path
| timer     | Scheduled jobs            |modern alternative to cron ex:logrotate.timer
| slice     | Resource management       |CPU, memory limits ex:system.slice, user.slice
| scope     | External processes        |processes not started by systemd ex:ssh sessions

>journalctl -u <servicename>                                      :logs for a particular service(for debugging service failures)
ex: journalctl -u nginx
>journalctl --since "yyyy-mm-dd" --until "yyyy-mm-dd"             :logs between two timestamps
supported time formats:      
"YYYY-MM-DD"
"YYYY-MM-DD HH:MM:SS"
"1 hour ago"
>journalctl -f                                                    :follow logs in real-time(ctrl+c to stop)
>journalctl -p <severity>                                         :show logs with mentioned severity level
Severity levels:
| Level   | Meaning                 |
| ------- | ----------------------- |
| emerg   | System unusable         |
| alert   | Immediate action needed |
| crit    | Critical                |
| err     | Errors                  |
| warning | Warnings                |
| notice  | Normal but significant  |
| info    | Informational           |
| debug   | Debugging               |
>dmesg -T                                                         :kernel ring buffer messages(boot logs, hardware detection, driver messages), messages since last boot...-T for timestamps
journalctl shows (system + service) logs; dmesg shows kernel messages.



System resource monitoring
>free -h                                        :memory usage(human readable)
>vmstat                                         :CPU, memory, swap space, IO statistics:useful for performance debugging
>iostat                                         :Disk IO performance(needs sysstat package)
>mpstat -P ALL                                  :CPU usage per core



Load and performance
>watch uptime                                   :continuously monitor load average
>watch -n 1 "ps aux --sort=-%cpu | head"        : top cpu consuming processes
Load average > CPU cores = system stress
Load ≈ number of CPU cores → OK



Service management
>systemctl status <service>                     :check service health
>systemctl start/stop/restart <service>         :controlling services
>systemctl enable <service>                     :start a service on boot
systemctl > service (for modern Linux)

pstree                                          :visualize tree of processes

Background & Job Control(Shell level)
