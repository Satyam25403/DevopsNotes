/ :Root of the filesystem — everything starts here.

===============================================================================================================================================

/bin :Essential user binaries (command line programs like: ls, cp, mv, cat) required for basic system operation.
File & directory operations             :ls, cp, mv, rm, mkdir, rmdir, pwd
File viewing & manipulation             :cat, tac, head, tail, sort, uniq, wc 
Text processing                         :grep, sed 
Shell & scripting                       :bash(GNU Bourne Again Shell), sh(POSIX-compliant shell), dash(lightweight shell (Ubuntu))
User/session commands                   :login, logout, su(switch user)
System & environment utilities          : echo, date, hostname, uname, true(return success: exit 0), false(return failure: exit 1)
Compression & archiving                 : tar, gzip, gunzip, zcat

🔹 /bin vs /usr/bin
Modern distros often symlink /bin → /usr/bin
Historically separate for recovery mode
Check:
ls -ld /bin

=================================================================================================================================

/sbin :System binaries used by admin/root/sudoers for booting, repairing, networking, and system control and administration.

User & group administration: useradd, usermod, userdel, groupadd, groupmod, groupdel

Filesystem & disk management: 
/sbin/fsck        : filesystem consistency check
/sbin/fsck.ext4   : check ext4 filesystem
/sbin/mkfs        : create filesystem
/sbin/mkfs.ext4   : format ext4 filesystem
/sbin/mount       : mount a filesystem
/sbin/umount      : unmount a filesystem
/sbin/blkid       : show block device attributes

Boot & system control:
/sbin/reboot      : reboot system
/sbin/poweroff    : shut down system
/sbin/halt        : stop system
/sbin/init        : system initialization (legacy)
/sbin/shutdown    : schedule shutdown/reboot

Networking & firewall:
/sbin/iptables    : configure kernel firewall
/sbin/ip          : network configuration tool
/sbin/route       : show/modify routing table (legacy)
/sbin/ifconfig    : configure interfaces (legacy)

Hardware and kernel utilities:
/sbin/lsblk       : list block devices
/sbin/fdisk       : disk partitioning
/sbin/parted      : advanced partition tool
/sbin/swapon      : enable swap
/sbin/swapoff     : disable swap
/sbin/sysctl      : modify kernel parameters

System services and modules:
/sbin/modprobe    : load/unload kernel modules
/sbin/lsmod       : list loaded kernel modules
/sbin/service     : manage services (SysVinit compatibility)

/sbin vs /usr/sbin
/sbin → essential admin binaries
/usr/sbin → non-essential admin binaries
Modern systems often symlink:
/sbin → /usr/sbin

/dev :Device files representing hardware (disks, USB, terminals)and virtual devices.
These are not real files — they are interfaces to kernel drivers...no data stored on disk
/dev is managed by udev, devices appear and disappear automatically, kernel handles read/write operations

Block devices (disks):
/dev/sda        : first SATA/SCSI disk
/dev/sda1       : first partition on sda
/dev/nvme0n1    : NVMe SSD device
/dev/loop0      : loopback device (ISO, snaps)

Virtual memory devices:
/dev/ram0       : RAM disk

Terminal devices:
/dev/tty        : current terminal
/dev/tty0       : system console
/dev/tty1       : virtual terminal
/dev/ttyS0      : serial port

Pseudo terminals(used by SSH and terminal emulators):
/dev/pts/0      : SSH terminal
/dev/pts/1      : another pseudo-terminal

Special virtual devices:
/dev/null       : discards all data written to it
/dev/zero       : outputs infinite zero bytes
/dev/random     : cryptographic random data (blocking)
/dev/urandom    : non-blocking random data
/dev/full       : always returns "disk full"

System control devices:
/dev/console    : system console
/dev/kmsg       : kernel log messages

Shared memory(used by browsers, databases, containers):
/dev/shm        : shared memory (tmpfs)

Disk aliases:
/dev/disk/by-uuid/      : stable disk identifiers
/dev/disk/by-label/     : disk labels
/dev/disk/by-id/        : hardware IDs
Used in /etc/fstab (recommended)

Device mapper (LVM, encryption):used by LVM, dm-crypt, Docker, Kubernetes
/dev/mapper/vg0-root    : logical volume

What happens when you plug a USB?
Device detected (udev)
Filesystem identified
Mount point created: /media/<user>/<LABEL>
Device mounted automatically

Useful commands with media:
lsblk                 # See disks & mount points
mount | grep media
df -h | grep media

Unmount safely:
umount /media/alice/USB_DRIVE

/var :Variable data that grows over time and changes frequently(variable runtime data).
Logs
Caches
Queues
Spool files
Databases (sometimes)

/var
├── log/
├── lib/
├── cache/
├── spool/
├── tmp/
├── run/        -> /run (symlink)
├── mail/
├── opt/
└── www/

System and service logs:
/var/log
├── syslog
├── messages
├── kern.log
├── auth.log
├── boot.log
├── dmesg
├── journal/
│   └── <machine-id>/
├── nginx/
│   │   ├── access.log
│   │   └── error.log
├── apache2/
└── mysql/...and so on

Application state data:
/var/lib
├── docker/
├── mysql/
├── postgresql/
├── systemd/
├── rpm/
├── dpkg/
└── kubelet/

Cached data:(usually safe to clean)
/var/cache
├── apt/
├── yum/
├── man/
└── fontconfig/

Queued jobs: used for delayed processing
/var/spool
├── cron/
├── mail/
├── cups/
└── at/

/var/tmp                            :persistent temp files(survives reboot)
/var/run                            :/run(symlink)...has legacy compatibility
/var/mail or /var/spool/mail        :local user mail storage
/var/www                            :web server root(commonly web apps hosted here)...used by Apache and nginx
└── html/
    ├── index.html
    └── app/
/var/opt                            :runtime data for /opt apps

==============================================================================================================================================

/srv: Holds data that is served by system services(Service data directory(FHS-defined))
✔ Not binaries
✔ Not configs
✔ Not logs
✔ Pure service content

/srv
├── www/          # Web content (HTML, static files)
├── ftp/          # FTP uploads/downloads
├── git/          # Git repositories
├── nfs/          # NFS exported directories
├── tftp/         # TFTP boot files
└── api/          # API served data
...and so on

🔹 What does “served data” mean?
Data that:
Clients request
Services expose
Users download/access

Examples:
Website files
Git repos
FTP uploads
Media streaming files

Example use case: a webserver using /srv/www
/srv/www/myapp
├── index.html
├── assets/
└── uploads/

configured in nginx:
/etc/nginx/nginx.conf

logs go to:
/var/log/nginx
