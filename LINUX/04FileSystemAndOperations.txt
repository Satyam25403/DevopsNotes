>umask                                      :list default permissions for new files/directories
umask defines the default permission mask for new files and directories created by a process (shell, script, service). It is process-specific, not global by default.
umask REMOVES permissions from the system’s default permissions. It does not assign permissions directly.

Default permissions(before umask):
| Type        | Default           |
| ----------- | ----------------- |
| Files       | `666` (rw-rw-rw-) |umask never sets execute on files. Files never get execute by default(you must specify explicitly)
| Directories | `777` (rwxrwxrwx) |
ex: umask = 002
This means:
Owner → remove nothing
Group → remove nothing
Others → remove write (2)

case1 : if umask set in a terminal: umask 002           :this applies to that shell session and all child processes started from it and not to other terminal sessions, 
other users and system services
case2 : if it is set in shell config files(this is persistent)
If set in:
~/.bashrc
~/.bash_profile
~/.profile
~/.zshrc
Applies to: Every new shell for that user

if set in:
/etc/profile
/etc/bashrc
/etc/login.defs
Example (/etc/login.defs):      UMASK 002       👉 Applies to: All users, All login shells

Systemd services do NOT inherit your shell’s umask.

IO and Redirection errors
2> /dev/null :(discard error output), > :(overwrite output), >> :(append output)
<command> 2> /dev/null                      :forward error logs to that directory(ignore all output)
<command> > output.log 2> error.log         :forward output to output.log and error to error.log(seperate output and error logs)
<command> > output.log 2> &1                :forward output as well as error to same place(output.log)
<command> >> output.log 2>&1                :append instead of overwrite
<command> 1>/dev/null 2>error.log           :log only errors

Inodes: An inode (index node) is a data structure that stores metadata about a file.An inode does NOT store the filename or file data.
when you do:
cat file.txt

Linux:
Looks up file.txt in directory
Finds inode number
Uses inode to locate data blocks
Reads file content
🔹 Inodes & directories
A directory:
Is a file
Has its own inode
Stores filename → inode mappings

Get inode details:
>ls -li

Check inode usage:
>df -i

Links:A link is simply another name or reference to a file.
🔹 1️⃣ Hard Links
A hard link points directly to the file’s inode
Multiple filenames → same actual data on disk -> same inode
No “original vs copy” concept
📌 Think of it as:
Two names, one file

Creating hard links:
>ln <original.txt> <hardlink.txt>

Deleting one name does not delete the data
File is deleted only when link count = 0
File exists as long as at least one hard link exists
If original file is deleted → hard link still works

2️⃣ Soft Links (Symbolic Links)
A soft link is a shortcut to another file. Soft link has its own inode
Stores path of the target file

📌 Think of it as:
Pointer → file path

It stores the path to target file
If target is deleted → broken symlink

Creating soft links:
>ln -s original.txt symlink.txt
