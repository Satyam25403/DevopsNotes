WHY TCP/IP WON THE INTERNET
HISTORY WHY?
THE REAL STORY
1974
Vint Cerf & Bob Kahn publish TCP/IP. ARPANET (predecessor to the internet) adopts it immediately and starts running.
1984
ISO publishes the OSI model — a more thorough, 7-layer academic standard meant to replace TCP/IP. But the internet was already running TCP/IP.
1990s
OSI protocols (X.25, CLNS) never gain traction. TCP/IP is already everywhere — impossible to replace. OSI becomes a teaching model only.
TODAY
Everyone uses TCP/IP. Engineers say "Layer 3 security group" or "Layer 7 WAF." OSI is used only for education and debugging conversations.
📚 OSI
Use for: learning, debugging, vendor-neutral discussions, certifications (CompTIA, CCNA).
🌐 TCP/IP
Use for: actual networking, cloud docs, Wireshark, writing firewall rules, everything real.
PRO TIP
When an AWS doc says "Layer 4 load balancer" — that IS OSI L4 (Transport). Both models agree at L3 and L4. The ambiguity is only at the top and bottom.
THE VERDICT:
TCP/IP ships. OSI teaches.
Both say the same thing at L3 and L4.

REAL TOOLS MAP TO REAL LAYERS
REAL WORLD CLOUD
EVERY TOOL LIVES AT A SPECIFIC LAYER
🔥
FIREWALL (STATEFUL)
Inspects TCP/UDP headers. Allows or blocks based on IP + port. Classic "port 22 = allow SSH."
OSI L3 OSI L4 TCP Transport
☁️
AWS SECURITY GROUP
Rules like "allow TCP port 443 from 0.0.0.0/0" — that's L3 (IP range) + L4 (port). Classic cloud L3/L4 control.
OSI L3 OSI L4 AWS SG
🛡️
WAF (WEB APP FIREWALL)
Reads HTTP headers, URLs, cookies, request bodies. Can block SQLi, XSS. Only possible at L7 — must understand HTTP.
OSI L7 TCP App AWS WAF
⚖️
LOAD BALANCER
L4 LB routes by IP+port (faster). L7 LB routes by URL path, cookie, hostname (smarter). AWS NLB = L4. ALB = L7.
L4 = NLB L7 = ALB
🔌
NETWORK SWITCH / NIC
Operates at L2 (MAC addresses). Your home router does L2 + L3. Physical cables and NICs are pure L1.
OSI L2 OSI L1 TCP Net Access
CLOUD SECURITY:
Security Group = L3/L4. WAF = L7.
Knowing the layer tells you its power & limits.
