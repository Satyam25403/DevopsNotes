HOW OSPF WORKS
1. Routers flood link-state advertisements (LSAs) to all others.
2. Every router builds the same map of the network (LSDB).
3. Dijkstra's algorithm finds shortest path from source to all dests.
4. Cost = bandwidth-based (lower bandwidth = higher cost).
OSPF KEY FACTS:
Link-state. Dijkstra's shortest path.
All routers share the same topology map.

HOW BGP WORKS
1. Routers in different ASes form TCP sessions (port 179) — called BGP peers.
2. Peers advertise their IP prefixes: "I can reach 1.2.3.0/24."
3. BGP chooses best path using policy attributes (AS-PATH, LOCAL-PREF, MED).
4. Unlike OSPF, BGP doesn't optimise for speed — it follows policy.
BGP KEY FACTS:
Path-vector. Policy-driven. TCP port 179.
Every ISP, cloud provider runs BGP.

BGP IS TRUSTED — AND THAT'S DANGEROUS
BGP HIJACKING ATTACK
BGP HAS NO BUILT-IN AUTHENTICATION
⚠ THE FUNDAMENTAL PROBLEM
BGP was designed in 1989 on the assumption that all ASes are trusted peers. A router accepting a BGP advertisement has no way to verify the sender actually owns those IP prefixes.
HOW BGP HIJACKING WORKS
1
Attacker's router announces "I own 1.2.3.0/24" via BGP.
2
Other routers accept the advertisement — no verification.
3
Traffic meant for the real 1.2.3.0/24 is rerouted to attacker.
4
Attacker can drop, intercept, or inspect packets. MiTM or blackhole.
REAL-WORLD INCIDENTS
2010: China Telecom accidentally re-routed 15% of internet traffic through China for 18 minutes.
2018: Russian ISP hijacked Google/AWS prefixes for 1 hour.
2022: Multiple nation-state BGP hijacks targeting financial infrastructure.
THE FIX — RPKI (Resource Public Key Infrastructure)
Cryptographically signs route origin — proves an AS is authorised to announce a prefix. Adoption is growing but not universal. Only ~50% of internet routes are RPKI-protected in 2024.
BGP HIJACKING:
Announce fake routes → steal traffic.
RPKI adds crypto signatures to fix this.

HOW TRACEROUTE WORKS
Sends packets with TTL=1, then 2, then 3… Each router decrements TTL. When it hits 0, the router sends back an ICMP "Time Exceeded" — revealing its IP and location. You see every hop.

READING THE OUTPUT
Hop 1: Your gateway — always private IP.
Hop 3: BGP peering point — ISP handoff.
Hop 4+: Inside destination AS (Google).
* * *: Router blocking ICMP or firewall drop — not necessarily a problem.
CONNECTING IT ALL
The jump from hop 2 → 3 in the traceroute is a BGP peering point — the boundary between your ISP's AS and another. OSPF handles hops within each AS. BGP decides the inter-AS handoff.
