SYN COOKIES
ENCODE STATE IN SEQUENCE NUMBER
DEFENSE #1 SYN COOKIE
WITHOUT vs WITH SYN COOKIES
01
Without SYN cookies: server allocates memory for each SYN. Millions of SYNs → table full → server stops accepting legit connections.
02
With SYN cookies: server encodes connection state into the SYN-ACK sequence number using HMAC(src_ip, src_port, dst_port, timestamp). No memory allocated.
03
When the ACK arrives, server verifies the cookie by recomputing the HMAC. Valid → allocate connection. Fake SYN from flood → no ACK → zero memory used. Flood is neutralized.
04
Check and enable: sysctl net.ipv4.tcp_syncookies (should be 1). Persist: add to /etc/sysctl.conf. Also tune: tcp_max_syn_backlog, tcp_synack_retries.
SYN COOKIE TRICK
State travels in the packet, not in server RAM
The genius: cryptographic proof of the handshake lives in the sequence number field TCP already uses. No protocol changes. No new fields. Completely backwards-compatible.

STATEFUL FIREWALL
TRACK SESSIONS · DROP OUT-OF-STATE · IPTABLES
DEFENSE #2+3 FIREWALL
TRAFFIC FILTERED BEFORE REACHING SERVER
IPTABLES RULES — COPY-PASTE READY
# allow established sessions
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
# rate limit new SYNs per source IP
iptables -A INPUT -p tcp --syn -m limit \
  --limit 10/s --limit-burst 20 -j ACCEPT
iptables -A INPUT -p tcp --syn -j DROP
# drop invalid packets
iptables -A INPUT -m state --state INVALID -j DROP
# default deny
iptables -P INPUT DROP
01
Stateful firewall tracks connection state (NEW, ESTABLISHED, RELATED, INVALID). Only ESTABLISHED packets pass without scrutiny. NEW packets must pass rate checks first.
02
Rate limiting: max 10 new SYNs per second globally (tune per source with hashlimit module). Burst of 20 allows legitimate spikes. Anything beyond → DROP. SYN flood neutralized even without SYN cookies.
STATEFUL FIREWALL
Track sessions. Only established packets pass freely.
The -m state --state ESTABLISHED rule is the most important line in any iptables config. All other rules are secondary. Without this, every packet fights to get through.

⚠ MySQL and Redis are world-exposed!
# fix: bind to 127.0.0.1 in config files
FIX — BIND TO LOCALHOST ONLY
# MySQL: in /etc/mysql/my.cnf
bind-address = 127.0.0.1
# Redis: in /etc/redis/redis.conf
bind 127.0.0.1
# If remote access needed: use SSH tunnel
ssh -L 3306:localhost:3306 user@server
01
ss -tlnp (or netstat -tlnp on older systems) shows all listening TCP sockets with the process name. Run this on every server. Anything unexpected is a risk. Schedule it weekly.
02
Databases (MySQL :3306, Redis :6379, PostgreSQL :5432) should NEVER bind to 0.0.0.0. Bind to 127.0.0.1 and use SSH tunnels for remote access. Thousands of breaches from exposed Redis alone.
03
Open ports you don't own are free footholds. An attacker's port scan takes ~2 seconds per host. Closing unnecessary ports doesn't slow legitimate traffic — it just reduces the attack surface to what you actually need.
