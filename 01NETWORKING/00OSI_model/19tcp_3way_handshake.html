WHY 3 MESSAGES?
Two messages aren't enough — the server would never confirm the client heard its SYN-ACK. Three is the minimum to prove both directions work and exchange sequence numbers reliably.

WHY SEQUENCE NUMBERS MATTER
ISN (Initial Sequence Number) is chosen randomly to prevent TCP hijacking. Both sides track:
SEQ = "this is byte N that I'm sending."
ACK = "I've received up to byte N, send N+1."
Out-of-order segments are reordered. Missing ones are retransmitted.
HANDSHAKE COMPLETE:
Both ISNs exchanged. Both dirs confirmed.
Now data can flow. State = ESTABLISHED.

SYN — Synchronise
Initiates a connection. Carries the ISN. Set only in first two messages of handshake. SYN flood = DDoS attack using half-open connections.
HANDSHAKE
ACK — Acknowledge
Confirms receipt of data. The ACK field says "I've received up to byte N." Set on virtually every packet after the first SYN.
ALMOST ALWAYS SET
FIN — Finish
Graceful teardown. Signals no more data from sender. Requires FIN-ACK exchange in both directions. Connection enters TIME_WAIT after.
TEARDOWN
RST — Reset
Abrupt connection termination. No handshake needed. Port closed = RST. Firewall drops = silence (no RST). Used in port scanners like nmap.
ABORT
PSH — Push
Tell receiver to pass data to app immediately — don't buffer. Seen in interactive sessions (SSH keystrokes, HTTP responses). Often set with last segment of a message.
FLUSH BUFFER
URG — Urgent
Marks data as urgent — process before the rest of the buffer. Rarely used in modern protocols. Historically used for out-of-band signals (e.g. Ctrl+C in Telnet).
LEGACY

TIME_WAIT — WHY IT EXISTS
After sending final ACK, client waits 2×MSL (≈60–120s) before fully closing. This ensures the final ACK arrives and any delayed packets from this connection have expired. Prevents old packets from corrupting a new connection on the same port pair.
TEARDOWN = 4 MESSAGES:
FIN → ACK → FIN → ACK
Each side closes independently. TIME_WAIT after.

RST — PORT CLOSED
Server receives SYN on a closed port. Sends RST immediately. Client gets "connection refused." nmap uses this to detect closed ports vs open ports.
SILENCE — FIREWALL DROPS
Firewall silently drops the SYN. Client waits, retransmits (×3), then times out. Slower than RST — can take 75s+. nmap marks this "filtered."
SYN FLOOD ATTACK
Attacker sends millions of SYNs (spoofed src IP). Server sends SYN-ACKs that never get ACKed — half-open connections fill the table. Defense: SYN cookies (don't allocate state until ACK arrives).
RST vs SILENCE:
RST = port closed. Silence = firewall drop.
SYN flood fills half-open table. Use SYN cookies.
