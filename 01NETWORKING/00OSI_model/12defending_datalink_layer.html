Layer 2 (the switch layer) has zero security enabled by default. Any device that can plug into your switch can poison ARP tables, impersonate DHCP, or hop VLANs.
!
Firewalls, IDS, and TLS all operate at Layer 3+. They never see L2 attacks. The only fix is switch configuration — and most switches ship with everything disabled.

5 settings. One afternoon. DAI + 802.1X + DHCP Snooping + VLANs + DTP off blocks the vast majority of LAN-based attacks. Let's enable them one by one.

DHCP SNOOPING
Watches DHCP traffic. Only "trusted" uplink ports can send OFFER/ACK. Any rogue DHCP reply from an access port is silently dropped.
ip dhcp snooping vlan 10
OFF
🔍
DYNAMIC ARP INSPECTION
Uses the DHCP snooping binding table as ground truth. Any ARP reply with an IP→MAC mismatch is dropped at the port before reaching any host.
ip arp inspection vlan 10
OFF
HOW THEY WORK TOGETHER
①
DHCP snooping logs every IP→MAC→port lease in a binding table
②
DAI checks every ARP reply against that table
③
ARP spoof attempt: attacker's fake 192.168.1.1→EVIL:MAC doesn't match table → DROPPED
✓
Rogue DHCP server reply comes from access port → DROPPED before any client sees it
ATTACKS BLOCKED ▼
✕ ARP SPOOFING / POISONING
✕ ROGUE DHCP SERVER
✕ MAN-IN-THE-MIDDLE (L2)
!
DHCP snooping must be enabled first — DAI depends on its binding table. If you enable DAI on a VLAN without snooping, all ARP traffic is dropped (hosts go offline).
WHY IT WORKS
ARP has no auth — the switch now provides it
The DHCP binding table is ground truth: lease issued by the real server = the only valid IP→MAC mapping. Attacker can't fake a binding entry they never received.

HOW 802.1X WORKS
①
Device plugs in → port is in UNAUTH state — only EAP frames pass
②
Device sends credentials to RADIUS server (cert, username/pw, or MAB)
③
RADIUS says ACCEPT → switch opens port, assigns VLAN
✕
No credentials → port stays blocked. Attacker gets NOTHING — not even a DHCP address
