STEALTH HALF-OPEN
FULL CONNECT vs HALF-OPEN (SYN SCAN)
kali@attacker:~$
# stealth SYN scan (half-open, requires root)
$ nmap -sS 192.168.1.1
# detect service versions
$ nmap -sV 192.168.1.1
# scan UDP ports (DNS, SNMP, NTP)
$ nmap -sU 192.168.1.1
# aggressive: OS detect + scripts
$ nmap -A 192.168.1.1
Nmap done: 1 IP (1 host up) scanned in 2.34s █
01
SYN scan (-sS) sends SYN, reads SYN-ACK (open) or RST (closed), then immediately sends RST to abort. Server never logs a completed connection. Requires root privileges.
02
-sV grabs the service banner — what version of nginx/OpenSSH? Cross-reference with CVE database → instant vulnerability list.
03
-sU (UDP scan) is slower but crucial: DNS (53), SNMP (161), NTP (123) run UDP and are often misconfigured amplification vectors.
SYN SCAN
Half-open = sees everything, leaves no log
The RST prevents the 3-way handshake completing. Modern systems detect SYN scan patterns by volume — not individual packets.

SYN FLOOD ATTACK
EXHAUST THE CONNECTION TABLE · DDOS
ATTACK SYN FLOOD
SYN FLOOD — CONNECTION TABLE FILLS UP
01
Each SYN allocates an entry in the server's half-open connection table. Server sends SYN-ACK and waits for ACK. With spoofed IPs, the ACK never arrives. Table fills.
02
Once the table is full, legitimate connections are rejected. Server is still running — just can't accept new connections. Classic DDoS without hacking anything.
03
SYN cookies: server doesn't allocate a table entry until ACK arrives. Encodes state in the SYN-ACK sequence number. Stateless — immune to SYN flood. Default on Linux since kernel 2.6.
SYN FLOOD
Half-open connections fill the table. Legit traffic dies.
Default Linux SYN backlog: 128–1024 entries. A 1Gbps attacker exhausts it in milliseconds. SYN cookies + BCP38 rate limiting = combined fix.

GITHUB 2018 + DEFENSES
1.35 Tbps INCIDENT · SYN COOKIES · RATE LIMITING
REAL WORLD + DEFENSES
GITHUB DDoS — FEB 28, 2018
17:21 UTC
Traffic spikes to 1.35 Tbps. Source: 50,000+ memcached servers on UDP 11211. Amplification factor: 51,200×.
17:21
GitHub absorbs 1.35 Tbps for ~10 minutes. git push/pull fails globally.
17:30
GitHub activates Akamai Prolexic scrubbing. Attack traffic dropped upstream. Normal in minutes.
Root cause
Memcached servers publicly exposed on UDP 11211 with no auth. 1 byte request → 100KB response.
🍪
SYN COOKIES
Server encodes connection state into SYN-ACK sequence number. No table entry allocated until ACK arrives. net.ipv4.tcp_syncookies=1 — enable in Linux.
🚦
RATE LIMITING + BCP38
ISPs drop packets with spoofed source IPs (BCP38). Firewalls rate-limit SYN per source IP. iptables --syn -m limit --limit 1/s -j ACCEPT
☁
ANYCAST SCRUBBING (Cloudflare/Akamai)
Traffic routed to scrubbing centers globally. Legitimate traffic forwarded; attack dropped. What saved GitHub in 9 minutes.
🔒
CLOSE THE SCAN SURFACE
Firewall all unused ports. Default-deny inbound. nmap yourself before attackers do.
KEY INSIGHT
SYN cookies cost nothing. Enable them everywhere.
Check now: sysctl net.ipv4.tcp_syncookies. Should return 1. If 0, your server is vulnerable.
