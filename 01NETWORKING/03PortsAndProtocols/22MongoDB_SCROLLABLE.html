🔒 FIX 1 — ENABLE AUTH
Set security.authorization: enabled in mongod.conf. Create admin user first, then restart. Every connection now requires credentials.
🌐 FIX 2 — BIND LOCALHOST
Set net.bindIp: 127.0.0.1. MongoDB only accepts connections from the same machine. Remote access via SSH tunnel only.
🛡️ FIX 3 — FIREWALL RULE
Block port 27017 at the firewall/cloud security group. Defence in depth — even if bindIp is misconfigured, the port is unreachable from the internet.
📖 THE GENERALISED LESSON
MongoDB was not unique. Redis, Elasticsearch, Cassandra, and Memcached all had identical mass-exploitation events from the same root cause: no auth by default + cloud-exposed port. Always check what a new database binds to before deploying.
Auth + localhost bind + firewall = three independent layers of protection.
Any single layer would have stopped the entire 2017 wave cold.
