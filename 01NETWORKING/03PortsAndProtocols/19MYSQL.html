STEP 2 — FILE READ/WRITE OS ESCALATION
FILE privilege = read any OS file MySQL can access, write to any location MySQL can write.
READ OS FILES WITH LOAD_FILE()

HARDENING & FIXES
STEP 3 — REMEDIATION FIX IT
Five changes that make this attack chain impossible.
# /etc/mysql/mysql.conf.d/mysqld.cnf
bind-address = 127.0.0.1
# Blocks all remote connection attempts
ALTER USER 'root'@'localhost'
  IDENTIFIED BY 'str0ng_R@ndP4ss!';
DELETE FROM mysql.user WHERE User='';
# Remove anonymous accounts too
# Dedicated app account — minimum privilege
CREATE USER 'appuser'@'127.0.0.1' IDENTIFIED BY '...';
GRANT SELECT, INSERT, UPDATE, DELETE
  ON myapp.* TO 'appuser'@'127.0.0.1';
# NO FILE, NO SUPER, NO GRANT OPTION
# Explicitly revoke FILE if it exists
REVOKE FILE ON *.* FROM 'root'@'%';
DROP USER 'root'@'%'; # remote root

SECURITY RULE
MySQL should never be reachable from the internet. App users get SELECT/INSERT only on their schema. FILE privilege is a foot-gun — remove it from every non-root account, and keep root localhost-only.
bind=127.0.0.1, strong root, dedicated app user, no FILE privilege.
