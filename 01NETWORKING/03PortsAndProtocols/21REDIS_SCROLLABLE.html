4 CONTROLS THAT STOP THIS ATTACK
DEFENCE FIX NOW
🔒 FIX 1 — requirepass
# /etc/redis/redis.conf
requirepass Str0ng!RandPass#92xK
Enforces authentication on every connection. Use a long random password — Redis AUTH is fast to brute-force without rate limiting.
🌐 FIX 2 — bind 127.0.0.1
# /etc/redis/redis.conf
bind 127.0.0.1
# or VPC-internal IP only
Loopback-only binding makes port 6379 unreachable from outside the machine entirely. Also enforce with firewall rules (iptables / security groups).
🚫 FIX 3 — rename CONFIG
# /etc/redis/redis.conf
rename-command CONFIG ""
rename-command SAVE ""
rename-command DEBUG ""
Empty string disables the command entirely. Rename to a secret token instead of "" if you still need it for ops. SLAVEOF and FLUSHALL also worth disabling.
👤 FIX 4 — non-root user
# systemd unit override
User=redis
Group=redis
# redis user has no shell, no SSH
Even if all else fails, a non-privileged user can't write to /root/.ssh. Defense in depth: each layer limits blast radius independently.
CONTROL EFFECTIVENESS
Apply all four controls — each one independently breaks the attack chain.
Bind + non-root + no CONFIG = this exploit is fully mitigated.
