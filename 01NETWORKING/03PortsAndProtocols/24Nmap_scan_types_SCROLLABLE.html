TCP CONNECT SCAN
-sT · FULL THREE-WAY HANDSHAKE
TCP CONNECT NOISY
terminal
$ nmap -sT 10.0.0.1
No root required — uses OS connect()
Full connection appears in target's logs
TCP FULL CONNECT — -sT SCAN
⚡ WHEN TO USE -sT
Use when you can't get root (shared hosting, CI pipelines, Docker without privileges). Also use when you need accurate results through complex NAT/load-balancer chains where raw packets get mangled.
✗ DOWNSIDE
Every open port generates a full connection entry in syslog, Apache access logs, nginx logs, and application audit trails. Blue teamers will see you.
-sT uses the OS network stack — no raw sockets, no root required.
Full connection = fully logged. Noisiest TCP scan method.

UDP & ACK SCANS
-sU FINDS HIDDEN SERVICES · -sA MAPS FIREWALLS
UDP + ACK PROTOCOL
-sU · UDP SCAN
$ nmap -sU -p 53,161,123 10.0.0.1
Sends UDP probe → if ICMP port-unreachable comes back = closed. No reply = open|filtered. Slow — waits for timeout each port.
SERVICES ONLY FOUND BY -sU
:53 DNS
zone xfer, cache poison, tunneling
:161 SNMP
community strings, config dump
:123 NTP
amplification DDoS, monlist
:67 DHCP
starvation, rogue server
-sA · ACK SCAN (FIREWALL MAPPING)
$ nmap -sA 10.0.0.1
Does NOT detect open/closed. Sends bare ACK — only tells you if a firewall is filtering or the port is unfiltered (reachable).
-sA RESPONSE MEANINGS
RST received
→ UNFILTERED — packet reached the host, no stateful firewall blocking it
No reply
→ FILTERED — firewall is dropping packets silently (stateful FW present)
ICMP error
→ FILTERED — firewall sending explicit reject (rare, informative)
Always combine -sU with TCP scans — UDP services are invisible to SYN/Connect.
-sA doesn't find open ports — it maps your path through the firewall first.

NULL · FIN · XMAS
-sN / -sF / -sX · FIREWALL BYPASS TRICKS
STEALTH FLAGS BYPASS
-sN · NULL SCAN flags: NONE
Sends packet with zero TCP flags. RFC 793 says closed ports must RST. Open/filtered ports don't respond. Bypasses stateless packet filters that only check SYN.
-sF · FIN SCAN flags: FIN
Sends FIN without an established connection — illegal per RFC. Closed ports RST. Open ports silently drop it. Same bypass logic as NULL with a FIN bit.
-sX · XMAS SCAN flags: FIN+PSH+URG
"Lit up like a Christmas tree" — all 3 obscure flags set. Same RFC 793 behaviour as NULL/FIN. Most recognisable pattern in IDS signatures.
RESPONSE INTERPRETATION (NULL / FIN / XMAS)
RST/ACK
Port is CLOSED
No reply
Port is OPEN or FILTERED (ambiguous)
ICMP error
Port is FILTERED by firewall
⚠ CRITICAL LIMITATION
These scans don't work on Windows. Microsoft's TCP stack sends RST for all malformed packets — both open and closed ports respond identically. Use only against Linux/BSD/Unix targets.
NULL/FIN/Xmas exploit RFC 793 — the same spec from 1981 still governs this.
Ambiguous open|filtered result is the price of bypassing stateless filters.
