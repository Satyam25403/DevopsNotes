5-STEP PIPELINE
step 1 — ping sweep
$ nmap -sn -PR 10.0.0.0/24 -oN hosts.txt
Starting Nmap 7.94 scan of /24...

Host: 10.0.0.14 (webserver) — Up

FLAG BREAKDOWN
-sn
No port scan — ping only. Much faster across large subnets.
-PR
ARP ping — works on local subnets even when ICMP is blocked.
-oN
Save output to file. Always output — every later step reads this list.
📄
OUTPUT → hosts.txt
List of live IPs. Feed this into every subsequent step.
Never scan 65,535 ports against an unknown subnet — start with who's alive.
-PR is ARP-based: works even when firewalls drop ICMP pings.

WIDE SCAN STEP 2/5

step 2 — fast scan
$ nmap -sS --top-ports 1000 -T2 --open
      -iL hosts.txt -oN fast.txt
Scanning 4 hosts [1000 ports each]
PORT   STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https
445/tcp open  microsoft-ds
3306/tcp open  mysql
FLAG BREAKDOWN
--top-ports 1000
nmap's most common 1000 ports — covers ~95% of real services fast.
-T2
Polite timing — slower but avoids triggering rate-based IDS.
--open
Only show open ports — cuts output noise significantly.
-iL hosts.txt
Read targets from the file saved in step 1.
⚡ WHY -T2 NOT -T4?
-T4 (aggressive) floods the target with packets. On shared infrastructure or IDS-monitored networks it drops packets and misses ports. -T2 is slower but more accurate. Use -T4 only in CTF/lab environments.
📄
OUTPUT → fast.txt
Open ports per host. Feeds step 3 prioritisation and step 4 targeting.
Top-1000 gives a fast actionable picture before the full scan finishes.
Run step 3 in the background while you analyse step 2 results.

STEP 3 — ALL 65,535 PORTS · BACKGROUND
FULL SCAN STEP 3/5
🔍 WHY SCAN ALL 65,535?
Admins hide services on non-standard ports: SSH on 2222, RDP on 33389, web apps on 8080/8443/8888. The top-1000 scan misses them. Always run -p- eventually.
step 3 — full scan (background)
$ nmap -sS -p- -T2 -iL hosts.txt
      -oN full.txt &
Scanning 65535 ports per host...
[running in background — takes 10-30min]
22/tcp   open ssh
80/tcp   open http
2222/tcp open ssh   <-- HIDDEN!
8080/tcp open http  <-- HIDDEN!
33389/tcp open ms-wbt <-- HIDDEN!
PARALLEL EXECUTION STRATEGY
Step 2 finishes → launch Step 3 in background
Step 3: -p- scan running in bg (&)
Meanwhile: analyse step 2 → run step 4
Step 4: -sC -sV on known open ports
📄
OUTPUT → full.txt
Complete port list including hidden services. Merge with step 2 findings.
The & background operator lets you run step 4 while step 3 grinds through ports.
Hidden non-standard ports are where the most interesting findings hide.

STEP 4 — -sC -sV ON OPEN PORTS ONLY
SERVICE ENUM STEP 4/5
⚡ WHY NOT -p- WITH -sV?
Running -sV against 65,535 ports sends service probes to every port — extremely slow and very noisy. Always run version detection only against known open ports from steps 2 and 3.
📄
INPUT: open ports from fast.txt + full.txt
step 4 — version + default scripts
$ nmap -sC -sV -p 22,80,443,445,3306,8080
      -iL hosts.txt -oN versioned.txt
PORT     STATE SERVICE  VERSION
22/tcp   open  ssh     OpenSSH 7.4
80/tcp   open  http    Apache 2.2.34
| http-title: Admin Login
445/tcp  open  smb     Windows 7
| smb2-security-mode: signing disabled
3306/tcp open  mysql   MySQL 5.5.62
| mysql-empty-password: root has no pwd!
🎯 FINDINGS IN THIS OUTPUT
→ Apache 2.2.34 — EOL, many CVEs
→ Windows 7 SMB — likely EternalBlue candidate
→ MySQL root no password — critical exposure
📄
OUTPUT → versioned.txt
Service versions + default script output. Drives step 5 targeted scripts.
Version numbers are your primary attack surface map. Old versions = CVEs.
-sC default scripts often flag misconfigs before you even run targeted scans.
