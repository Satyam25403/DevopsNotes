THE FIX: MSS CLAMPING
MSS CLAMPING THE FIX
Can't fix broken ICMP everywhere.
MSS clamping intercepts TCP handshake
and forces a smaller segment size.
MTU vs MSS:
ETH
14B
IP
20B
TCP
20B
MSS = 1460B
← MTU = 1500B (full frame) → MSS = MTU−40B
HOW CLAMPING INTERCEPTS SYN:
①
TCP SYN, MSS=1460→
🔧 iptables TCPMSS rule:
rewrites MSS → 1360
(VPN MTU 1420 − 60B headers)
②
SYN, MSS=1360 →
③
Server uses 1360B segments — always fits! ✓
THE ACTUAL FIX COMMANDS:
# For VPN interface (tun0)
iptables -t mangle -A FORWARD \
  -p tcp --tcp-flags SYN,RST SYN \
  -o tun0 \
  -j TCPMSS --clamp-mss-to-pmtu
# Or set fixed MSS (VPN MTU−40):
iptables -t mangle -A FORWARD \
  -p tcp --tcp-flags SYN,RST SYN \
  -j TCPMSS --set-mss 1360
VERIFY IT'S WORKING:
$ ping -M do -s 1400 8.8.8.8
If no reply → MTU problem confirmed.
$ ip route show cache
Shows cached PMTU per destination.
