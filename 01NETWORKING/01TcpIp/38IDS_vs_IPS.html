IDS vs IPS
SNORT RULES & WHEN TO USE EACH
SNORT / SURICATA RULES
Snort rules are human-readable. Each field has a specific meaning.
# SQL injection attempt on HTTP
alert tcp any any -> any 80 (
  msg:"SQLi attempt";
  content:"1=1"; nocase;
  sid:1000001; rev:1;
)
# IPS mode: DROP the packet
drop tcp any any -> any 22 (
  msg:"SSH brute force";
  detection_filter:
    track by_src, count 5, seconds 60;
  sid:1000002;
)
# IDS mode: alert = log only, never blocks
alert keyword → log + notify (IDS)
drop keyword → block packet (IPS mode)
WHEN TO USE WHICH
USE IDS
Need visibility without risk
Prod traffic you can't afford to drop
Initial deployment / tuning phase
USE IPS
Known-good traffic patterns established
Low tolerance for attack reach
Must have fail-open bypass hardware
BOTH
IDS for east-west (internal) traffic
IPS at perimeter (north-south)
Tune signatures on IDS before promoting to IPS
INTERVIEW ANSWER
"Deploy IDS first — tune rules until false positives are minimal. Promote to IPS only at the perimeter with fail-open bypass. Run anomaly detection alongside for zero-day coverage."
alert = IDS mode. drop = IPS mode. Same rule syntax, different action.
Tune on IDS, promote to IPS. Always deploy fail-open bypass hardware inline.
