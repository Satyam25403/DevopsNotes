WITHOUT HEALTHCHECK
THE LIE
Without HEALTHCHECK, Docker marks a container "Up" the instant its process starts. It never checks whether the app inside is actually serving traffic. A crashed app looks identical to a healthy one.
Process running ≠ application healthy. Docker can't tell the difference.
A crashed app shows "Up" in docker ps. No HEALTHCHECK = blind.

SYNTAX, OPTIONS & WHAT THEY DO
THE SYNTAX DOCKERFILE
Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY . .
RUN npm install
HEALTHCHECK \
--interval=30s \
--timeout=3s \
--start-period=10s \
--retries=3 \
CMD curl -f localhost:3000/health \
|| exit 1
OPTIONS EXPLAINED
--interval How often to run the probe. Default 30s. Shorter = faster detection, more overhead.
--timeout Probe must complete within this. If it hangs longer, counts as failure. Default 30s.
--start-period Grace period after container start. Failures during this don't count. Lets app boot.
--retries How many consecutive failures before marking unhealthy. Default 3.
THE CMD PROBE
exit 0 = healthy. exit 1 = unhealthy. The curl -f flag makes curl exit non-zero on HTTP errors (4xx/5xx) — so a 500 response correctly fails the check. No curl? Use wget -q instead.
CMD exit 0 = healthy. exit 1 = unhealthy. That's all Docker checks.
curl -f fails on HTTP errors — making it a real health signal.

PRODUCTION USE
COMPOSE DEPENDS_ON + TIPS
REAL WORLD MUST KNOW
docker-compose.yml
services:
backend:
image: myapi
healthcheck:
test: ["CMD","curl","-f","localhost:5000"]
interval: 10s
frontend:
image: myui
depends_on:
backend:
condition: service_healthy
WHY THIS MATTERS
condition: service_healthy makes Compose hold the frontend until the backend passes its health probe. Without this, frontend starts before the backend API is ready — instant connection errors on boot.
PRODUCTION TIPS
✓
USE A DEDICATED /health ENDPOINT
Return 200 only when DB is connected, cache is warm, and the app is ready to serve. Not just "process is alive".
⚠
ALPINE IMAGES — NO CURL
Alpine has no curl by default. Either RUN apk add curl in the Dockerfile, or use wget -qO- localhost:3000/health || exit 1.
★
SWARM / K8S RESTART POLICY
In Swarm mode, unhealthy containers are restarted automatically. In Kubernetes use readiness/liveness probes instead — HEALTHCHECK is ignored.
condition: service_healthy waits for probe to pass before starting dependents.
HEALTHCHECK is the safety net every production Dockerfile needs.
