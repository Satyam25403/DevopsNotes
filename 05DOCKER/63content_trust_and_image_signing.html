⚠ DCT LIMITATIONS
Tied to Docker Hub's Notary v1. Key management is painful. No OCI-native support. Not portable across registries. Cosign replaces this.
DOCKER_CONTENT_TRUST=1 blocks unsigned images at pull time.
But DCT is old, registry-specific, and hard to manage.

THE MODERN CNCF APPROACH
COSIGN SIGSTORE
SIGSTORE COMPONENTS
cosign sign & verify
# sign (keyless — uses OIDC)
$ cosign sign ghcr.io/myorg/myapp:v1.0
Pushing signature to: ghcr.io/myorg/myapp
# verify before deploy
$ cosign verify --certificate-identity \
alice@company.com ghcr.io/myorg/myapp:v1.0
Verified OK ✓
Cosign stores signatures as OCI artifacts in the registry itself.
No key server needed. Works with any OCI-compatible registry.

KUBERNETES: ENFORCE AT ADMISSION
Use Kyverno or Connaisseur as admission webhooks. Any pod spec with an unsigned image is rejected before scheduling. No unsigned image ever runs on the cluster.
kyverno policy — verify signature
verifyImages:
- imageReferences:
- "ghcr.io/myorg/*"
attestors:
- entries:
- keyless: {rekor: sigstore}
# unsigned → pod rejected ✗
GitHub Actions signs on push using the workflow OIDC token.
Kyverno enforces — unsigned images never reach the cluster.
