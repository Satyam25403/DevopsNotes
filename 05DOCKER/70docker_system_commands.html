WHAT IS A DANGLING IMAGE?
After docker build rebuilds an image,
old layers with no tag become
<none>:<none> — dangling junk.
Safe to delete — no container uses them.
🧹 SAFE WEEKLY CRON
docker system prune -af
# -a: all unused images -f: no prompt
Add to crontab → disk never fills.
prune removes stopped containers, dangling images, networks.
Add --volumes carefully — permanent data loss.

🛡️ RUNNING CONTAINERS ARE SAFE
Prune never touches images used by a running container, active volumes, or named networks in use. It only removes truly orphaned resources.
Dangling images + stopped containers vanish. Running stays.
docker system prune never touches active resources.

SYSTEM EVENTS
REAL-TIME DAEMON STREAM
docker system events LIVE STREAM
📡 THE DEBUG TOOL NOBODY KNOWS
Streams every event from the Docker daemon in real time — container starts, stops, kills, OOM deaths, image pulls, network connects, volume mounts.
live stream
$ docker system events
# blocks and streams forever...
2024-01 container start abc123 (image=nginx)
2024-01 container die def456 (exitCode=1)
2024-01 container oom ghi789 (image=myapp)
2024-01 network connect abc123 bridge
2024-01 image pull nginx:latest
USEFUL FILTERS
# only container events
docker events --filter type=container
# only OOM kills (find memory issues)
docker events --filter event=oom
# last 10 minutes of events
docker events --since 10m
🐛 WHEN TO USE EVENTS
Container keeps restarting? Watch events
App running slow? Check for OOM events
Debugging CI flakiness? --since 1h
Events streams every daemon action in real time.
Filter by event=oom to catch silent memory kills.
