ANCHOR SYNTAX
&anchor — *alias — how it works
YAML SPEC SYNTAX
&anchor
DEFINE
Marks a block as a reusable anchor. Like declaring a variable.

&myanchor before a mapping block saves it.
*alias
REFERENCE
Inlines the anchor's content wherever used. Like calling a variable.

*myanchor expands the full block.
minimal example
# define the anchor
logging_cfg: &logging
driver: json-file
options:
max-size: 10m
# use the alias
services:
api:
logging: *logging
worker:
logging: *logging
scheduler:
logging: *logging
MERGE KEY: <<
api:
<<: *logging
image: myapp
Merges anchor keys into an existing mapping. Override individual keys after the merge.
YAML anchors are part of the YAML spec — not Compose-specific.
Define once with & — reference anywhere with *.

COMPOSE FEATURE IGNORED BY COMPOSE
x- EXTENSION FIELDS COMPOSE IGNORES THEM
Any top-level key starting with x- is
silently ignored by docker compose.
This makes them perfect anchor holders
— define reusable blocks at the top
of your file, reference everywhere.
docker-compose.yml
x-logging: &logging
driver: json-file
options:
max-size: 10m
x-deploy: &deploy
resources:
limits: {cpus: '0.5', memory: 512M}
services:
api:
logging: *logging
deploy: *deploy
worker:
logging: *logging
deploy: *deploy
x- keys are a Compose convention — not standard YAML.
x-logging, x-env, x-deploy: named anchors at the top of your file.
