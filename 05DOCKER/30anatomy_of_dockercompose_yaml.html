▶
services: — the top-level key. Everything inside is a named container. Think of it as your app's guest list.
▶
image: — pull a pre-built image from Docker Hub (or a registry). postgres:15 means "official postgres, version 15".
▶
build: — build from a local Dockerfile instead of pulling. Path points to the folder containing your Dockerfile.
image:
Use when you want an existing published image. No source code needed.
build:
Use when you have a Dockerfile and want Compose to build the image for you.
Every service is one container. Give it a name, then tell it where to get its image.
image: pulls. build: compiles your Dockerfile.

HOW PORTS WORK: HOST:CONTAINER
▶
ports: "HOST:CONTAINER" — left side is your laptop, right side is inside the container. 3000:3000 opens localhost:3000 to the container's port 3000.
▶
environment: — inject env vars into the container. Note DB_HOST: db — services find each other by their service name. No IP addresses needed.
💡 PRO TIP: env_file
Don't hardcode secrets! Use env_file: .env to load from a .env file and add .env to .gitignore.
env_file: .env ← reads KEY=VALUE pairs from file
Ports bridge your laptop and the container. Env vars configure the app.
Services talk to each other using their name as hostname.

▶
depends_on: — controls startup order. Compose starts db before web. Prevents "can't connect to database" errors on boot.
HOW NAMED VOLUMES WORK
▶
volumes: — declare once at top-level (pgdata:), mount inside a service. Data survives docker compose down. Use down -v to wipe it.
NAMED VOLUME
pgdata:/var/lib/...
Docker manages location. Best for databases.
BIND MOUNT
./src:/app/src
Maps a local folder. Best for live code reload.
Volumes persist data beyond container lifetime. depends_on orders startup.
Delete container, keep data. pgdata: survives restarts.

HOW TO READ ANY COMPOSE FILE
1. Count the services — how many containers?
2. Check image: vs build: — pulled or local?
3. Look at ports: — what's exposed to localhost?
4. Read environment: — what config does it need?
5. Check volumes: — what data persists?
→ Then just: docker compose up
services → image/build → ports → env → volumes → depends_on.
