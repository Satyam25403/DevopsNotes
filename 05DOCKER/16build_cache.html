CACHE RULES & PATTERNS
WHAT INVALIDATES CACHE · BEST PRACTICES
RULES PATTERNS
WHAT INVALIDATES A LAYER'S CACHE
①
The instruction text changes — e.g. RUN npm install → RUN npm ci
②
A COPY/ADD file content changes — file hash is checked, not just name
③
Any parent layer was invalidated — cascades down to ALL children
THE SAME PATTERN — ALL LANGUAGES
Node
COPY package*.json ./
RUN npm ci
COPY . .
Python
COPY requirements.txt ./
RUN pip install -r requirements.txt
COPY . .
Go
COPY go.mod go.sum ./
RUN go mod download
COPY . .
Ruby
COPY Gemfile Gemfile.lock ./
RUN bundle install
COPY . .
BONUS TIPS
npm ci vs npm install → ci is faster, deterministic, fails on lockfile mismatch
.dockerignore → exclude node_modules, .git, *.md from COPY . . context
--mount=type=cache → BuildKit cache mounts for pip/npm persist between builds
Multi-stage builds → separate builder stage keeps final image small
THE RULE IN ONE SENTENCE
Stable dependencies first. Changing source code last.
This pattern works for every language: copy the manifest (package.json / requirements.txt / go.mod) before copying source. That's it. 1 line swap. 22× faster builds.
