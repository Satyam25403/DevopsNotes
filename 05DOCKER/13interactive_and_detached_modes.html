-d vs -it MODES
BACKGROUND vs TERMINAL TAKEOVER
THE FLAGS OVERVIEW
TWO WAYS TO RUN A CONTAINER
🔕
-d DETACHED
Container runs in background. Terminal is immediately returned to you. No output shown. Daemon babysits the process.
docker run -d nginx:alpine
⌨️
-it INTERACTIVE
Container attaches to your terminal. stdin open. You get a live shell or REPL. Ctrl+D or exit to leave.
docker run -it ubuntu bash
WHAT -i AND -t ACTUALLY MEAN
-i = keep stdin open even if not attached
-t = allocate a pseudo-TTY (fake terminal)
Together they wire your keyboard → container process.
Without both, typing does nothing.
-i = stdin -t = tty always pair them
QUICK DECISION RULE
Running a server / daemon? → use -d
Need a shell / REPL / debug? → use -it
Ran with -d but need in? → docker exec -it
-d = fire and forget. -it = I'm going in.
Most production containers run -d. You use -it for debugging, one-off scripts, or interactive tools like a Python REPL.

docker exec -it — GET A SHELL INTO A RUNNING CONTAINER
1.
docker run -d nginx
start nginx detached — no shell
2.
docker exec -it web sh
open a shell into the RUNNING container
3.
ls / cat / curl …
poke around. container keeps running when you exit.
4.
exit
shell closes. nginx still running. -d container unaffected.
exec into running container
$docker exec -it web sh
/ #nginx -v

/ #exit

$docker ps

$
exec -it = shell in, container stays up
Unlike docker run -it where exit stops the container, docker exec just closes your shell session. The container keeps running.
