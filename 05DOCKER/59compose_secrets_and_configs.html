WHY ENV VARS ARE DANGEROUS
THE PROBLEM VULN

image: myapp:latest
environment:
- DB_PASS=s3cr3tP@ssw0rd

ANY USER CAN RUN ▼
docker inspect app_container
"Env": [
"DB_PASS=s3cr3tP@ssw0rd",
"API_KEY=sk-abc123xyz",
...]
☠️ ENV VARS LEAK IN 3 PLACES
▸ docker inspect → plaintext JSON
▸ ps aux / /proc → visible to all users
▸ crash logs → dumped to stdout
Environment variables are stored in container metadata in plaintext.
docker inspect exposes ALL env vars — no auth required.

🔐 FILE-BASED SECRETS
COMPOSE SECRETS SYNTAX
THE FIX SAFE
docker-compose.yml ✓
services:
app:
image: myapp:latest
secrets:
- db_password
- api_key
secrets:
db_password:
file: ./secrets/db_pass.txt
api_key:
file: ./secrets/api_key.txt
MOUNTED INSIDE CONTAINER AT
app reads secret in code
# Python example
with open('/run/secrets/db_password') as f:
password = f.read().strip()
Secrets are mounted as read-only tmpfs files — never written to disk.
Invisible to docker inspect. Only the container reads them.

configs in compose

📁 DEFAULT MOUNT PATHS
secrets → /run/secrets/<name>
configs → /<name> (root by default)
use target: to set custom path
Configs work like secrets but are NOT encrypted in Swarm mode.
Use configs for non-sensitive files. Use secrets for credentials.

💡 OUTSIDE SWARM NOTE
Without Swarm, secrets are still file-mounted and hidden from docker inspect — but the host file is NOT encrypted. Use Swarm or an external vault (HashiCorp, AWS Secrets Manager) for full at-rest encryption.
File-based secrets beat env vars in every threat model. Low cost, high value.
Zero code cost. Just change compose.yml and read from /run/secrets/.
