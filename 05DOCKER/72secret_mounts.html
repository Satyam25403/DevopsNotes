BUILDKIT SECRETS
RUN --mount=type=secret
THE RIGHT WAY SAFE
✓ GOOD Dockerfile
# syntax=docker/dockerfile:1
FROM node:20-alpine
RUN --mount=type=secret,\
id=npm_token,\
target=/run/secrets/npm_token \
NPM_TOKEN=$(cat /run/secrets/npm_token) \
npm install
SECRET LIFECYCLE
✨ HOW IT WORKS
The secret is mounted as a tmpfs file inside that single RUN step. When the RUN step finishes, the mount is gone. It never touches any image layer — not even as a deleted file.
Secret injected as tmpfs for ONE RUN step only.
Gone when the step ends. Zero layer residue.

BUILD COMMAND
PASSING SECRETS TO BUILDX
--secret FLAG BUILDX
terminal
$ docker buildx build \
--secret id=npm_token,src=./npm_token.txt \
--secret id=aws_key,src=~/.aws/credentials \
-t myapp:latest .
ALTERNATIVE: FROM ENV VAR
# Secret from env var, not file
$ export NPM_TOKEN=npm_abc123
$ docker buildx build \
--secret id=npm_token,env=NPM_TOKEN \
-t myapp:latest .
SECRET SOURCES
src=./file.txt — from a file
env=VAR_NAME — from env var
src=- — from stdin pipe
$ cat secret.txt | docker buildx build \
--secret id=key,src=- .
💡 REQUIRES BUILDKIT
Add # syntax=docker/dockerfile:1 as the very first line of your Dockerfile. BuildKit is the default since Docker 23.0 — no extra setup needed on modern Docker.
--secret id=name,src=file binds the secret at build time.
Can use file, env var, or stdin as the secret source.

RUN --mount=type=secret,id=npm_token \

🔐 SECRET MOUNT OPTIONS
id=name → secret identifier
target=path → mount path (default: /run/secrets/<id>)
required=true → fail build if secret missing
mode=0400 → file permissions (default 0400)
Same pattern for npm, pip, AWS — mount, use, gone.
Add required=true to fail fast if secret is missing.
