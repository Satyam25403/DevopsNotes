CONTAINER LIFECYCLE — NO POLICY
WHY THIS IS DANGEROUS
The default restart policy is no. A crashed container stays dead. No alert fires. No auto-recovery. Your service is down until someone notices and manually restarts it. Every production container needs a restart policy.
Default policy is "no" — crashes stay crashed. Always explicit.
A container without a restart policy is one crash away from downtime.

WHICH ONE TO CHOOSE?
always
Critical services that must never stay down. Databases, proxies, core APIs.
unless-stopped
Services you sometimes stop intentionally (dev tools, scheduled jobs, staging).
"always" ignores docker stop. "unless-stopped" remembers it.
The difference only shows after the Docker daemon itself restarts.

RETRY SEQUENCE — on-failure:3
WHEN TO USE on-failure
Jobs and workers that exit 0 on completion — you don't want those restarted. Workers that might fail transiently (network blip, DB not ready) but should retry a limited number of times before giving up and alerting.
check retry count
$ docker inspect myworker \
--format '{{.RestartCount}}'
3
on-failure only restarts on non-zero exit. exit 0 = stay stopped.
:N caps restarts. Without N it retries forever on every crash.

PICK YOUR POLICY
ALL FOUR OPTIONS — WHEN TO USE EACH
CHEATSHEET REFERENCE
ALL RESTART POLICIES
POLICYBEHAVIOURPROD?
no Never restarts. Default. Crash = stay dead. ✕
always Always restarts — even after docker stop and daemon reboot. Ignores manual stops. ✓
unless-stopped Restarts on crash and daemon reboot, but respects docker stop. Best of both worlds. ✓✓
on-failure[:N] Only on non-zero exit. Ignores daemon restart. Cap with :N. Good for workers/jobs. ~
PRODUCTION TEMPLATE
# Long-running service (API, proxy, DB)
docker run -d \
--restart unless-stopped \
--name api myapi
# One-shot job / worker with retries
docker run \
--restart on-failure:5 \
--name worker myworker
VERIFY YOUR POLICY IS SET
Run docker inspect api --format '{{.HostConfig.RestartPolicy.Name}}' to confirm the policy is what you set. Surprises here are common after copy-pasting run commands.
unless-stopped is the right default for most production services.
Every docker run in production needs an explicit --restart flag.
