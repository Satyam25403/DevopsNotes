🐳 THE FLAT NETWORK
EVERYONE TALKS TO EVERYONE
⚠ THE PROBLEM SECURITY RISK
default bridge — no isolation
💀 BREACH SCENARIO
XSS in frontend → attacker runs SQL queries directly against postgres. Game over.
⚠ ALSO WRONG
All services share one DNS namespace. Any container can resolve any other by name.
On the default bridge, all containers see each other. Nothing is isolated.
Your frontend should never be able to speak to your database. Ever.

🌐 CUSTOM NETWORKS
SCOPED DNS + REAL ISOLATION
THE CONCEPT HOW IT WORKS
two custom networks — different scopes
🔍 SCOPED DNS
Containers only resolve names of services on the same network. frontend can resolve "api" but NOT "database".
🌉 API BRIDGES BOTH
The API service joins both networks. It's the only path from front to back. Database is invisible to the frontend zone.
Custom networks give each zone its own isolated DNS namespace.
If you're not on the network, you can't even resolve the hostname.

🧠 THE MENTAL MODEL
frontend-net = public zone
Faces users. Minimal trust.
API = DMZ (demilitarised zone)
Translates public ↔ private.
backend-net = private zone
No public access. Ever.
Bridge for local, overlay for clusters. Same isolation model, different scope.
Public zone → DMZ → private zone. Classic defence-in-depth.
