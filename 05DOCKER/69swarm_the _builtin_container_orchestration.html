STEP 1 — SWARM INIT BOOTSTRAP
ONE COMMAND TO RULE THEM ALL
Swarm turns a Docker host into a manager node. Other machines join as workers. The manager schedules containers across the cluster. No external orchestrator needed.
manager node
$ docker swarm init --advertise-addr 10.0.0.1
Swarm initialized: current node is now a manager.
To add a worker to this swarm, run:
docker swarm join --token SWMTKN-1-...

STEP 2 — DOCKER SERVICE REPLICAS

You declare: run 5 replicas of nginx. Swarm makes it happen — scheduling tasks across workers, restarting failures, maintaining desired count.
manager
$ docker service create \
--name web \
--replicas 5 \
--publish published=80,target=80 \
nginx:alpine

DOCKER SWARM COMMAND REFERENCE
STEP 6 — REFERENCE SUMMARY
CLUSTER LIFECYCLE
docker swarm init — bootstrap manager
docker swarm join — add a worker node
docker swarm join-token — get join token
docker node ls — list all nodes
docker node update — drain / promote
SERVICE MANAGEMENT
docker service create — deploy a service
docker service ls — list services
docker service ps — list tasks/replicas
docker service update — rolling update
docker service scale — change replica count
docker service rm — remove service
STACK & SECRETS
docker stack deploy — deploy from YAML
docker stack ls — list stacks
docker stack rm — tear down stack
docker secret create — store a secret
docker config create — store a config
MENTAL MODEL
Compose = dev + local multi-container
Stack = Compose YAML on a Swarm cluster
Service = one image, N replicas, managed
Task = one running container instance
Swarm = built-in, zero deps. K8s = more power, more complexity.
For small teams: swarm init + stack deploy + overlay nets is enough.
