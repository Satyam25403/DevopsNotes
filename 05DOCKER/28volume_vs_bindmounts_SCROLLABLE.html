VOLUME ANATOMY
🏭 USE VOLUMES WHEN...
• Database files (postgres, mysql, mongo)
• Sharing data between containers
• Deploying to any machine (CI/CD)
• Backing up with docker volume inspect
⚠️ VOLUME GOTCHAS
• Volume persists after container removal
• Run docker volume prune to clean up
• First mount copies image content in
Docker stores data in /var/lib/docker/volumes/. No host path needed.
Volumes survive container removal and work on any host.

BIND MOUNT — DIRECT HOST ACCESS
✅ GOOD: USE BIND MOUNTS FOR
• Hot reload during local dev
• Injecting config files at runtime
• Reading host logs / sockets
🚫 NEVER USE BIND MOUNTS FOR
• Database files in production
• Multi-host / Swarm / K8s deploys
• Secrets (use tmpfs instead!)
• CI/CD pipelines on fresh runners
Container gets direct read/write access to your host filesystem.
Misconfigured permissions can let a container escape to the host.
