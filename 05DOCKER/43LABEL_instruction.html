INSPECT & FILTER
QUERY LABELS AT THE COMMAND LINE
QUERYING LABELS POWERFUL
READ ALL LABELS ON AN IMAGE
$ terminal
docker inspect \
  --format '{{json .Config.Labels}}' \
  my-app:1.0.0
OUTPUT
{
  "maintainer": "alice@corp.com",
  "version": "1.0.0",
  "git.commit": "a3f9c1b",
  "build.date": "2025-05-21"
}
FILTER IMAGES BY LABEL VALUE
$ find all images on version 1.0.0
docker images \
  --filter label=version=1.0.0
RESULTS — ONLY MATCHING IMAGES
my-app version=1.0.0 ✓
api-service version=1.0.0 ✓
worker version=2.1.0 ✗
$ filter by key existence (any value)
docker images \
  --filter label=git.commit
→ returns any image that has git.commit set
docker inspect reads labels. --filter queries them.
Filter by key alone or key=value for exact match.

OCI STANDARD LABELS
org.opencontainers.image.*
OCI IMAGE SPEC BEST PRACTICE
📋 OCI IMAGE SPEC — THE STANDARD
The Open Container Initiative defines standard
label names under the prefix
org.opencontainers.image.*
Tooling (registries, scanners, CI) understands these.
OCI STANDARD LABEL NAMES
…image.title human-readable name
…image.description short description
…image.version semver e.g. 1.0.0
…image.created ISO 8601 build date
…image.revision git commit SHA
…image.source source repo URL
…image.authors maintainer email
…image.licenses SPDX identifier e.g. MIT
…image.url image documentation URL
DOCKERFILE WITH OCI LABELS
LABEL \
  org.opencontainers.image.title="my-app" \
  org.opencontainers.image.version="1.0.0" \
  org.opencontainers.image.revision="a3f9c1b" \
  org.opencontainers.image.created="2025-05-21T10:00:00Z"
Use org.opencontainers.image.* for portability.
Registries and scanners understand OCI labels natively.

🏷️

CI pipeline script (GitHub Actions etc.)
docker build \
  --label org.opencontainers.image.revision=\
    $(git rev-parse HEAD) \
  --label org.opencontainers.image.created=\
    $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  -t my-app:1.0.0 .
