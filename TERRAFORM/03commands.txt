previously we used to directly apply

now, we will create a plan which will store the current config and then apply
terraform plan                          # Show the plan
terraform plan -out=<somefile>.plan     # Save the plan to a file (compiled version of config)
terraform apply <somefile>.plan         # Apply the saved plan

The .plan file is a binary execution plan—Terraform uses it to ensure that what you reviewed is exactly what gets applied, with no surprises.
🧠 Why This Matters
- ✅ Adds a layer of safety and review before applying changes
- ✅ Useful in CI/CD pipelines or team workflows
- ✅ Prevents drift between what was planned and what gets deployed

variables: two types
1.input
2.output



🧩 1. Input Variables
Used to parameterize your configuration—like passing arguments into a function.

🔧 Declare in variables.tf or directly in your .tf file:
variable "instance_type" {
  description = "Type of EC2 instance"
  type        = string
  default     = "t2.micro"
}

🧪 Use in a resource:
resource "aws_instance" "web" {
  ami           = "ami-0c94855ba95c71c99"
  instance_type = var.instance_type         => reference that variable here
}

You can override the default using:
terraform apply -var="instance_type=t2.small"       (or)
terraform apply --var instance_type=t2.micro

or using some variables file:
- variables.tfvars file: 
instance_type = "t2.small"

---

a very practical use case!

📁 File Structure
terraform/
├── main.tf
├── variables.tf
└── variables.tfvars


📄 variables.tf – Declare Input Variables
variable "num_var" {
  type    = number
  default = 27
}
variable "access_key" {
  type = string
}
variable "secret_key" {
  type = string
}


📄 variables.tfvars – Provide Values
num_var     = 300
access_key  = "access"
secret_key  = "secret"


📄 main.tf – Use Variables in Resources
provider "aws" {
  region     = "ap-south-1"
  access_key = var.access_key
  secret_key = var.secret_key
}
resource "aws_instance" "example" {
  ami           = "ami-0c94855ba95c71c99"
  instance_type = "t2.micro"
  count         = var.num_var > 100 ? 2 : 1
}


🧪 Run Terraform with .tfvars
terraform init
terraform plan -var-file="variables.tfvars"
terraform apply -var-file="variables.tfvars"

This pattern is great for separating config from logic, especially in multi-environment setups (e.g., dev/staging/prod).



📤 2. Output Variables
Used to expose information after resources are created—like return values from a function.

🔧 Declare in outputs.tf or directly in your .tf file:
output "instance_ip" {
  description = "Public IP of the EC2 instance"
  value       = aws_instance.web.public_ip
}


terraform output instance_ip


These variables make your Terraform code modular, reusable, and clean.
