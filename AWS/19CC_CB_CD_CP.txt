Code Build: Continuous Integration
code => build => Deploy     : when all 3 are linked and automated, it is called: pipeline
the build step is where your raw code gets transformed into something usable—like a deployable artifact(testing, integrating and setting environment and packages)
each time u push a commit -> triggers a new build -> then comes live

in any build stage we will have a file which defines how the build should be
in aws this is done by something called buildspec.yml
version: 0.2
phases:
  install:
    commands:
      - echo "Installing dependencies (none needed for static site)"
  pre_build:
    commands:
      - echo "Preparing build directory..."
      - mkdir -p build
  build:
    commands:
      - echo "Copying index.html to build folder..."
      - cp index.html build/
  post_build:
    commands:
      - echo "Build complete. Ready for deployment."
artifacts:
  files:
    - build/index.html 

once u have this in sodecommit repo, go to build projects and create one
u need to create a service role in the process of creating a build

Code Deploy: Continuous Deployment

CodeDeploy takes your built code (like index.html) and deploys it to EC2, Lambda, or on-prem servers.

🔧 Setup Steps (EC2 Deployment)
1. Create EC2 Instance
- Use Amazon Linux 2
- Open ports: 22 (SSH), 80 (HTTP)
- Attach IAM role with AmazonEC2RoleforAWSCodeDeploy policy

2. Install CodeDeploy Agent on EC2
SSH into your instance and run:
sudo yum update -y
sudo yum install -y ruby wget
cd /home/ec2-user
wget https://aws-codedeploy-<region>.s3.<region>.amazonaws.com/latest/install
chmod +x ./install
sudo ./install auto
sudo service codedeploy-agent status


3. Add Deployment Files to Your Repo
appspec.yml (defines what to deploy and where)
version: 0.0
os: linux
files:
  - source: build/
    destination: /var/www/html/
hooks:
  ApplicationStart:
    - location: scripts/start.sh
      timeout: 300
      runas: ec2-user


scripts/start.sh (optional startup script)
#!/bin/bash
echo "Deployment complete!"


Make sure both files are in your CodeCommit repo.

4. Create CodeDeploy Application
- Platform: EC2/On-prem
- Deployment group:
- Choose EC2 instance using tags
- Attach service role with AWSCodeDeployRole policy

Code Pipeline: CI/CD Orchestration

CodePipeline connects CodeCommit → CodeBuild → CodeDeploy into one automated flow.

🛠️ Setup Steps
1. Create Pipeline
- Source: CodeCommit /repo/branch
- Build: CodeBuild project (uses buildspec.yml)
- Deploy: CodeDeploy application

2. Artifact Bucket
AWS will ask for an S3 bucket to store build artifacts. You can create one or use an existing bucket.

3. IAM Role
Pipeline needs a role with permissions for CodeCommit, CodeBuild, CodeDeploy, and S3.

🔄 Workflow Summary
1. You push code to CodeCommit
2. CodePipeline triggers CodeBuild
3. CodeBuild runs buildspec.yml → creates build/index.html
4. CodeDeploy deploys it to EC2 → /var/www/html/index.html


✅ Result
Your static site (index.html) is now live on EC2, and every commit triggers a fresh build and deployment—fully automated CI/CD.
