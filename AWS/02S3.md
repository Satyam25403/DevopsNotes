# Amazon S3 (Simple Storage Service)

Amazon S3 is AWS's flagship **object storage** service, designed for storing and retrieving any amount of data from anywhere on the internet. Unlike block storage (EBS) or file storage (EFS), S3 stores data as **objects** (file + metadata) inside **buckets**.

---

## Key Features

- **Unlimited Scalability**: Store petabytes of data — no provisioning needed.
- **High Durability**: 99.999999999% (11 nines) durability — data is replicated across multiple Availability Zones.
- **High Availability**: 99.99% availability SLA for S3 Standard.
- **Fine-Grained Permissions**: IAM policies, bucket policies, ACLs, and pre-signed URLs.
- **Versioning**: Keep multiple versions of objects for recovery or auditing.
- **Lifecycle Policies**: Automatically transition or delete objects based on age.
- **Event Notifications**: Trigger Lambda, SQS, or SNS on object events (e.g., upload).

---

## Common Use Cases

- **Backup & Restore**: Snapshots, logs, and disaster recovery data.
- **Static Website Hosting**: Serve HTML/CSS/JS directly from S3.
- **Data Lakes**: Centralize structured and unstructured data for analytics (e.g., with Athena).
- **Machine Learning**: Store training datasets and model outputs.
- **Archiving**: Use S3 Glacier for long-term, low-cost storage.
- **Application Assets**: Images, videos, user uploads for web/mobile apps.
- **CI/CD Artifacts**: Store build artifacts, deployment packages.

---

## Storage Classes

| Class | Use Case | Retrieval |
|-------|----------|-----------|
| S3 Standard | Frequently accessed data | Milliseconds |
| S3 Intelligent-Tiering | Unknown or changing access patterns | Milliseconds |
| S3 Standard-IA | Infrequently accessed, rapid retrieval | Milliseconds |
| S3 One Zone-IA | Infrequent access, single AZ (lower cost) | Milliseconds |
| S3 Glacier Instant Retrieval | Archive with millisecond access | Milliseconds |
| S3 Glacier Flexible Retrieval | Archive, cheap storage | Minutes to hours |
| S3 Glacier Deep Archive | Lowest cost, rarely accessed | Hours |

## Core CLI Commands

```bash
# List all buckets
aws s3 ls

# List objects in a bucket
aws s3 ls s3://my-bucket/
aws s3 ls s3://my-bucket/folder/ --recursive

# Create a bucket
aws s3 mb s3://my-bucket --region us-east-1

# Upload a file
aws s3 cp myfile.txt s3://my-bucket/

# Upload a folder
aws s3 cp ./local-folder s3://my-bucket/folder/ --recursive

# Sync local folder with bucket (only transfers changed files)
aws s3 sync ./local-folder s3://my-bucket/folder/

# Download a file
aws s3 cp s3://my-bucket/myfile.txt ./myfile.txt

# Delete an object
aws s3 rm s3://my-bucket/myfile.txt

# Delete a bucket and all contents
aws s3 rb s3://my-bucket --force
```

## Permissions & Access Control

### Bucket Policy (resource-based)
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::my-bucket/*"
  }]
}
```
This makes all objects in the bucket publicly readable (e.g., for a static website).

### Pre-signed URLs
Allow temporary, scoped access to private objects without changing bucket permissions:
```bash
# Generate a URL valid for 1 hour
aws s3 presign s3://my-bucket/private-file.pdf --expires-in 3600
```

## Versioning

Enable versioning on a bucket to keep a history of every object version:
```bash
aws s3api put-bucket-versioning \
  --bucket my-bucket \
  --versioning-configuration Status=Enabled
```

Once enabled, deleted objects get a **delete marker** instead of being permanently removed — you can restore them.

---

## Lifecycle Rules

Automate transitions to cheaper storage classes or deletion:
```json
{
  "Rules": [{
    "Status": "Enabled",
    "Filter": { "Prefix": "logs/" },
    "Transitions": [
      { "Days": 30, "StorageClass": "STANDARD_IA" },
      { "Days": 90, "StorageClass": "GLACIER" }
    ],
    "Expiration": { "Days": 365 }
  }]
}
```

## Static Website Hosting

1. Enable static hosting in bucket settings.
2. Set `index.html` as the index document.
3. Apply a public read bucket policy.
4. Access via the S3 website endpoint: `http://my-bucket.s3-website-us-east-1.amazonaws.com`

> **Tip**: Use **CloudFront** in front of S3 for HTTPS, custom domains, caching, and global CDN distribution.

## S3 vs EBS vs EFS

| Feature | S3 | EBS | EFS |
|---------|-----|-----|-----|
| Type | Object storage | Block storage | File storage |
| Access | HTTP/S (API) | Attached to one EC2 | NFS (multiple EC2s) |
| Scalability | Unlimited | Up to 64 TB/volume | Unlimited |
| Use case | Files, backups, web assets | OS disks, databases | Shared file system |
