Serverless computing

it lets you run code without provisioning or managing servers. You just upload your function, and AWS handles everything else: scaling, availability, and infrastructure.

⚙️ What AWS Lambda Does
- Event-driven execution: Lambda runs your code in response to events — like an HTTP request via API Gateway, a file upload to S3, or a message in an SQS queue.
- Automatic scaling: It scales from zero to thousands of requests per second, without any manual intervention.
- Pay-per-use: You’re billed only for the time your code runs — down to the millisecond.

🧱 What You Provide
- Your function code (Node.js, Python, Java, Go, etc.)
- Optional environment variables
- A trigger (e.g., API Gateway, S3, DynamoDB)
- IAM permissions for what your function can access

🧠 Real-World Use Cases
- REST APIs (via API Gateway + Lambda)
- File processing (triggered by S3 uploads)
- Scheduled jobs (via EventBridge cron rules)
- Real-time data transformation (e.g., Kinesis stream processing)
- Backend logic for mobile/web apps

🔐 Security & Integration
- Integrates with IAM for fine-grained access control
- Can connect to VPCs for private resources
- Works with RDS (via RDS Proxy), DynamoDB, S3, SNS, and more

🧩 Bonus: Lambda Layers & Custom Runtimes
- Layers let you share libraries across functions
- Custom runtimes allow you to use languages beyond the built-in ones

a sample nodejs lambda function:
exports.handler = async (event, context) => {
  console.log("Received event:", JSON.stringify(event));

  return {
    statusCode: 200,
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ message: "Hello from Lambda!" })
  };
};

- exports.handler: This is the entry point — AWS Lambda looks for this function when the event is triggered.
- event: Contains data from the trigger (e.g., API Gateway, S3, etc.)
- context: Metadata about the invocation (function name, memory limit, etc.)
