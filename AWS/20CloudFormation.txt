🏗️ AWS CloudFormation: Infrastructure as Code
CloudFormation lets you define and provision AWS infrastructure using code (YAML or JSON). 
You write a template, and AWS builds everything for you—like EC2, S3, IAM roles, etc.

AWS CloudFormation and Terraform(multi-cloud) are analogous, in that both are Infrastructure as Code (IaC) tools. 
They let you define cloud infrastructure using configuration files, so you can automate the creation of resources

🧱 Example Template Structure (High-Level)
Here’s how you break it down: something.yaml

AWSTemplateFormatVersion: '2010-09-09'
Description: ECS Fargate Deployment with VPC, IAM, ECR, and Service
Resources:
  ### S3 ###
  S3Bucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: hehe
      Tags:
        - Key: course
          Value: tutedude

  ### VPC ###
  MyVPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.0.0.0/16

  ### Subnets ###
  PublicSubnet1:
    Type: AWS::EC2::Subnet
    Properties:
      VpcId: !Ref MyVPC
      CidrBlock: 10.0.1.0/24

  ### Security Group ###
  ECSSecurityGroup:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: Allow HTTP
      VpcId: !Ref MyVPC
      SecurityGroupIngress:
        - IpProtocol: tcp
          FromPort: 80
          ToPort: 80
          CidrIp: 0.0.0.0/0

  ### IAM Role for ECS Task Execution ###
  ECSExecutionRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Statement:
          - Effect: Allow
            Principal:
              Service: ecs-tasks.amazonaws.com
            Action: sts:AssumeRole
      ManagedPolicyArns:
        - arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy

  ### ECR Repository ###
  MyECRRepo:
    Type: AWS::ECR::Repository
    Properties:
      RepositoryName: my-app-repo

  ### ECS Cluster ###
  MyECSCluster:
    Type: AWS::ECS::Cluster

  ### Task Definition ###
  MyTaskDefinition:
    Type: AWS::ECS::TaskDefinition
    Properties:
      RequiresCompatibilities: [FARGATE]
      Cpu: 256
      Memory: 512
      NetworkMode: awsvpc
      ExecutionRoleArn: !GetAtt ECSExecutionRole.Arn
      ContainerDefinitions:
        - Name: my-app
          Image: <your-ecr-image-url>
          PortMappings:
            - ContainerPort: 80

  ### ECS Service ###
  MyECSService:
    Type: AWS::ECS::Service
    Properties:
      Cluster: !Ref MyECSCluster
      DesiredCount: 1
      LaunchType: FARGATE
      TaskDefinition: !Ref MyTaskDefinition
      NetworkConfiguration:
        AwsvpcConfiguration:
          Subnets: [!Ref PublicSubnet1]
          SecurityGroups: [!Ref ECSSecurityGroup]
          AssignPublicIp: ENABLED

🧱 Example: Host a Static Website (index.html) on S3 via CloudFormation

1️⃣ Create Your Template File
Save this as s3-static-site.yaml:
AWSTemplateFormatVersion: '2010-09-09'
Description: Static website hosted on S3

Resources:
  StaticSiteBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: my-static-site-bucket
      WebsiteConfiguration:
        IndexDocument: index.html
        ErrorDocument: error.html
      AccessControl: PublicRead

  BucketPolicy:
    Type: AWS::S3::BucketPolicy
    Properties:
      Bucket: !Ref StaticSiteBucket
      PolicyDocument:
        Statement:
          - Effect: Allow
            Principal: "*"
            Action: "s3:GetObject"
            Resource: !Sub "${StaticSiteBucket.Arn}/*"


This template:
- Creates an S3 bucket
- Enables static website hosting
- Makes the contents publicly readable

2️⃣ Upload Your Files to S3
After the stack is created, upload your index.html and error.html manually or via CLI:
aws s3 cp index.html s3://my-static-site-bucket/index.html
aws s3 cp error.html s3://my-static-site-bucket/error.html



3️⃣ Deploy the Stack
You can deploy using the AWS Console or CLI:
aws cloudformation create-stack \
  --stack-name StaticSiteStack \
  --template-body file://s3-static-site.yaml \
  --capabilities CAPABILITY_NAMED_IAM



🧠 What CloudFormation Does Here
| Template | You define resources like S3, IAM, EC2 in YAML or JSON | 
| Stack | CloudFormation reads the template and provisions everything as a “stack” | 
| Reusability | You can reuse, version, and share templates across teams | 
| Automation | No manual clicking—just deploy infrastructure with one command | 




🔁 Real-World Flow
1. You write a template (YAML/JSON)
2. CloudFormation reads it and provisions resources
3. You upload your code (e.g., index.html)
4. Your infrastructure is live—automated and repeatable

========================================= PARAMETERS ======================================================

🧠 What Are Parameters?
Parameters let you pass custom values into your CloudFormation template at deployment time. 
Think of them like variables—they make your templates reusable and flexible.

🧾 Simple Example
Parameters:
  InstanceTypeParam:
    Type: String
    Default: t2.micro
    AllowedValues:
      - t2.micro
      - t2.small
      - t2.medium
    Description: Enter EC2 instance type


You can then use this parameter in your resource definition:
Resources:
  MyEC2Instance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !Ref InstanceTypeParam
      ImageId: ami-0abcdef1234567890



🔧 Why Use Parameters?
- Avoid hardcoding values (like instance types, bucket names, etc.)
- Customize stacks for dev, test, and prod environments
- Make templates dynamic and reusable

===================================================== OUTPUTS ====================================================

Absolutely! In AWS CloudFormation, the Outputs section lets you expose key information from your stack—like resource names, ARNs, or URLs—after deployment. This is super useful when you want to reference those values in other stacks or just need to grab them easily.

🧾 Example: Output for an S3 Bucket
Let’s say you created an S3 bucket in your template like this:
Resources:
  MyS3Bucket:
    Type: AWS::S3::Bucket


You can add an Outputs section to expose the bucket name and website URL:
Outputs:
  BucketName:
    Description: "Name of the S3 bucket(ARN)"
    Value: !GetAtt MyS3Bucket.Arn

  BucketWebsiteURL:
    Description: "Website endpoint of the S3 bucket"
    Value: !GetAtt MyS3Bucket.WebsiteURL



🧠 Why Use Outputs?
- Quickly access resource details after stack creation
- Reference values in other stacks (cross-stack exports)
- Display info in the CloudFormation console
- Use in automation scripts via CLI or SDK

================================================ A SIMPLE EXAMPLE ======================================================

Practical example of deploying a simple web app (like a static index.html) to an EC2 instance using AWS CloudFormation. 
This setup uses UserData to install a web server and serve your app automatically when the instance launches.

🏗️ CloudFormation Template: EC2 Web App Deployment
Save this as ec2-webapp.yaml:

AWSTemplateFormatVersion: '2010-09-09'
Description: Deploy a simple web app to EC2 using CloudFormation

Parameters:
  KeyName:
    Type: AWS::EC2::KeyPair::KeyName
    Description: Name of an existing EC2 KeyPair to SSH into the instance
  ImageId:
    Type: String
    Description: AMI ID of EC2 instance
    Default: ami-0c94855ba95c71c99  # Amazon Linux 2 (update for your region)

Resources:
  WebAppSecurityGroup:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupName: groupForWebapp
      GroupDescription: Allow HTTP access
      SecurityGroupIngress:             #inbound rules
        - IpProtocol: tcp
          FromPort: 22
          ToPort: 22
          CidrIp: 0.0.0.0/0
        - IpProtocol: tcp
          FromPort: 22
          ToPort: 22
          CidrIp: 0.0.0.0/0
      SecurityGroupEgress:             #outbound rules
        - IpProtocol: tcp
          FromPort: 80
          ToPort: 80
          CidrIp: 0.0.0.0/0

  WebAppInstance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: t2.micro
      KeyName: !Ref KeyName
      ImageId: !Ref ImageId
      SecurityGroups: [!Ref WebAppSecurityGroup]
      UserData:
        Fn::Base64: !Sub |
          #!/bin/bash
          yum update -y
          yum install -y httpd
          systemctl start httpd
          systemctl enable httpd
          echo "<h1>Hello from CloudFormation EC2!</h1>" > /var/www/html/index.html

Outputs:
  InstancePublicIP:
    Description: Public IP of the EC2 instance
    Value: !GetAtt WebAppInstance.PublicIp

  WebAppURL:
    Description: Access your app via this URL
    Value: !Sub "http://${WebAppInstance.PublicDnsName}"

NOTE:
always see in resources preview GUI before creating the stack

once provisioned, u can ssh into ur ec2:
ssh -i "priv_key.pem" linux@<ec2instanceip>

🔧 How to Deploy
- Go to AWS CloudFormation Console
- Click Create Stack → With new resources (standard)
- Upload the ec2-webapp.yaml file
- Provide your KeyPair name when prompted
- Click Next → Next → Create Stack

✅ Result
- EC2 instance launches
- Apache web server installs via UserData
- index.html is served at http://<PublicDNS>
- You can SSH into the instance using your key pair
