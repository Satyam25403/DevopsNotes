git init    =>initialise empty git repo in current working directory...(.git/ hidden directory with all necessary configs and requirements).

git status  =>Shows tracked/untracked files, and whether changes are staged or not.

git add .(or)<filename>         =>add untracked files to staging area(track the untracked)

git commit -m "message here"    =>after adding to staging area...command to make commit
Records a snapshot of the staged changes in the repo history.

git log                 =>Shows all commits with their IDs(commit hash-uuid), author, date, and messages.

git restore --staged <filename>         =>to remove the file that has been added to staging area accidentally(using git add)

git diff <commit hash>          =>shows difference between the commit where head is and the specified commit hash

git reset --hard <commit hash>      =>head back to some commit in the commit history undoing all commits committed after that one

git remote add origin <git@github.com:.....git>(git uri)             =>add a remote(github/gitlab/bitbucket or any other git provider) repo to local repository

git push        =>push committed changes to remote repo
git push <origin_name> <branch_name>            =>while pushing changes on some other branch
NOTE:origin_name: origin for github , gl for gitlab etc as conventions

git branch -a       =>list all branches(red: remote, greeen: local)

git branch new <branch_name>        =>create new branch(creates a replica of current head in the new branch)
git switch <branch_name>        =>switch to some branch

git checkout -b <branch_name>       =>create new branch and switch to it
git switch <branch_name>        =>change branch

if u havent made changes from github i.e. made changes in github editor directly or through some other device/someone else and have committed changes
those changes will not be available in local.....so to bring the updated contents from remote origin to local we use this command:
git pull


let say we want to merge two branches src:feature target:main/master branch
git switch <target i.e. master>
git merge <src i.e. feature>

git push            =>now two new commits will be created on the branches one on each...for the merge


doing this merging on github directly is called PR or pull request
pull requests=> create new pull request=>select the branch u need to merge to master=> preview changes=>create pull request=>commit a message=> the repo owner will accept


if same contents of files are changed in different ways in different branches, it leads to a merge conflict
which needs to be resolved manually=> git provides a nice interface to do this
