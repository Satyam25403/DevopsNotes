CONFIG & SENTINEL VS CLUSTER
PRODUCTION CONFIG WHEN TO USE
Sentinel config is minimal. Client does one extra lookup.
sentinel.conf
sentinel monitor mymaster 127.0.0.1 6379 2
sentinel down-after-milliseconds mymaster 5000
sentinel failover-timeout mymaster 60000
client: discover master via Sentinel
SENTINEL get-master-addr-by-name mymaster
→ "127.0.0.1" "6379"  (or new addr)
SENTINEL vs CLUSTER
SENTINEL
✓ 1 master (all data)
✓ Simple to operate
✓ HA without sharding
✓ Use when: <25GB data
✗ No horizontal scale
✗ All reads/writes: master
CLUSTER
✓ 16384 hash slots
✓ Horizontal scale-out
✓ Built-in HA per shard
✓ Use when: >25GB data
✗ Complex config
✗ No cross-slot MGET
INTERVIEW ANSWER
"For HA without needing to shard data, Sentinel is the right answer — simpler ops, fewer failure modes. Reach for Cluster only when a single node can't hold the dataset."
Sentinel = HA. Cluster = HA + horizontal scale. Pick the simpler one first.
Most apps never outgrow a single well-tuned Redis node with Sentinel.
