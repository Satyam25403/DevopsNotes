READ-THROUGH CACHE
THE CACHE THAT FETCHES ITS OWN DATA
THE IDEA PATTERN
"YOU'VE HEARD OF CACHE-ASIDE.
BUT WHAT IF THE CACHE FETCHED
THE DATA ITSELF?"
Used natively by: CDNs (Cloudflare),
Nginx proxy_cache, Varnish, NCache.
CACHE-ASIDE
App checks cache.
Miss? App fetches DB.
App writes to cache.
App has DB logic.
READ-THROUGH
App asks cache.
Miss? Cache fetches DB.
Cache writes itself.
App has NO DB logic.
THE KEY DIFFERENCE
In Cache-Aside: app orchestrates everything.
In Read-Through: cache is the smart layer.
App always talks to cache only.
Simpler app code. Cache owns the logic.
WHERE READ-THROUGH APPEARS IN THE WILD
🌐

🔁

🗄️
ORM-level caches
Hibernate 2nd-level, Spring Cache abstractions

⚠ THE WARM-UP PROBLEM
Both patterns share the same cold-start issue:
First request always goes to DB.
Fix: pre-warm the cache on deploy
by loading hot keys before traffic hits.
INTERVIEW ONE-LINER
"Read-Through moves the cache-miss logic
from the app into the caching layer itself.
App always calls cache. Cache calls DB.
It's how CDNs and caching proxies work."
