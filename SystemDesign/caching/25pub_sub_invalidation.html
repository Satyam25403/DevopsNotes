TRADE-OFFS DEPTH
The full production flow in one pipeline:
① APP SERVER — on DB write
BEGIN transaction
  UPDATE users SET name='Bob' WHERE id=123
COMMIT
② PUBLISH invalidation event
PUBLISH invalidate:user:123 "user:123"
③ EACH SUBSCRIBER receives & deletes
SUBSCRIBE invalidate:*
  on message → localCache.delete("user:123")
KEY TRADE-OFFS
✓ PROS
Zero shared memory — each cache is local (fast)
One PUBLISH fans out to all N servers
Redis pub/sub is fire-and-forget: ~1–5ms
⚠ CONS
Eventual consistency: ~1–5ms stale window
Sub disconnect = missed invalidations
Redis goes down = cache never cleared
↑ MITIGATION
Short TTL as safety net (e.g. 60s)
On reconnect: flush entire local cache
Pattern-subscribe: PSUBSCRIBE invalidate:*
Pub/sub gives broadcast invalidation in a single PUBLISH call.
Always pair with a short TTL as a safety net for missed messages.
